# 项目开发共享参考文档规则

## 总原则

以后所有长期项目、工具项目、Skill 项目，都要维护共享参考文档。

原因：用户本地会同时使用多个 AI 工具，不能把关键规则只留在某一次聊天窗口里。任何 AI 接手项目时，都应该能通过本地文档快速理解项目状态、规则、路径、待办和最近决策。

## 每个项目至少要有

1. 项目定位：这个项目到底解决什么问题。
2. 关键路径：代码、数据、输出、日志、缓存、备份在哪里。
3. 当前规则：用户确认过的判断标准和工作流。
4. 当前状态：已经完成什么、哪些东西不能动、哪些正在排队。
5. 待办清单：下一步应该怎么做。
6. 交接提示：其他 AI 工具应该先读哪些文件。
7. 更新记录：每次重要改变都要写一条增量记录。

## 默认落地位置

- 全局项目记忆：`D:\AICode\AI\memory\projects\<project-name>\`
- 项目内交接文档：`<project-root>\PROJECT_HANDOFF_PROMPT.md` 或 `<project-root>\PROJECT_REFERENCE.md`
- Skill 规则：`C:\Users\z\.codex\skills\<skill-name>\SKILL.md` 和 `references\`

## 写回规则

1. 用户明确纠正工作流、偏好、命名、判断标准时，必须写回项目参考文档。
2. 新增工具、脚本、批处理入口时，必须写明用途、调用方式、输入输出和限制。
3. 大批量素材处理必须保留清单、报告和可复核记录。
4. 不保存密钥、账号密码、敏感凭证。
5. 不把所有项目混在一起；每个项目有自己的项目记忆目录。
