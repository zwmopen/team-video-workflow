# 公众号贴图草稿模块实施计划

## 产品决策

右侧不嵌微信公众号后台网页。原因：

1. 草稿创建能力由官方 API 完成，不需要网页登录。
2. 公众号后台登录态、扫码和页面结构会增加不必要的不稳定性。
3. 后台页面通常不适合作为第三方本地页面 iframe 嵌入。
4. AppSecret 只留在本机服务端，不能进入前端页面。

右侧应承担“发布前检查台”的角色：

- 图片顺序；
- 标题和字数；
- 正文和字数；
- 超长警告；
- 账号选择；
- 测试模式；
- 草稿结果；
- 历史和重复检测。

## 下一阶段接口

### 批量队列

在现有单任务锁基础上增加可恢复队列：

```text
PENDING → UPLOADING_IMAGES → CREATING_DRAFT → DRAFTED / FAILED
```

### 公众号账号管理界面

只编辑：

- 账号显示名；
- AppID；
- AppSecret 对应的环境变量名；
- 作者名。

不在网页中显示或回传 AppSecret。

### 永久素材复用

同一公众号下，相同图片 SHA-256 优先复用已有 media_id；接口返回素材失效时再重新上传。

### 与 Win32 中控台合并

推荐增加一个新入口，不把 Python 业务逻辑重写进 `main.cpp`：

```text
素材投送中控.exe
└─ 公众号草稿
   └─ 启动/聚焦本地发布器页面
```

这样手机传送和公众号草稿是同一公司核心项目里的两个模块，但各自保持清晰边界。

## 真实账号验收条件

真实发布测试必须具备：

- 公众号 AppID；
- 公众号 AppSecret；
- 当前公网 IP 已加入白名单；
- 草稿接口权限；
- 素材接口权限。

第一轮只用 3 张测试图，确认：

- 草稿类型是贴图/newspic；
- 图片顺序正确；
- 第一张为首图；
- 标题和正文完整；
- 超过 1000 字时实际接口返回结果；
- 没有触发正式发表。
