# 微信公众号贴图草稿发布器 V0.1

这是 `team-video-workflow` 仓库内的独立模块，用于把本地成品库中的“图片 + TXT 文案”创建为微信公众号**图片消息/贴图（newspic）草稿**。

它只创建草稿，不正式发表，不模拟浏览器拖拽，也不需要在右侧登录微信公众号网页。

## 当前界面

- 左侧：本地成品库目录树。
- 右侧：图片顺序预览、标题编辑、正文编辑、字数提示、公众号账号、测试模式、草稿结果和最近记录。
- 顶部“打开公众号后台”：只在新窗口打开官方后台，便于人工检查，不嵌入 iframe。

## 支持的成品库结构

### 单独帖子

```text
成品库/
└─ 杭州团建帖子/
   ├─ 01.jpg
   ├─ 02.jpg
   └─ 文案.txt
```

### 作品集

```text
成品库/
└─ 桐庐作品集/
   ├─ 帖子A/
   │  ├─ 01.jpg
   │  └─ 文案.txt
   └─ 帖子B/
      ├─ 01.jpg
      ├─ 02.jpg
      └─ copywriting.txt
```

目录可以继续嵌套，默认最多扫描 5 层。只要某个文件夹同时包含图片和 TXT，它就会被识别为一篇完整帖子。

## 文案规则

- TXT 第一条非空行：标题。
- 其余内容：正文。
- 标题不超过 24 个可见字符：保持原文。
- 标题超过 24 个可见字符：生成不超过 20 字的建议标题，并保留原标题供人工调整。
- 正文超过 1000 字：只警告，不截断，不阻止保存草稿。
- 图片按自然顺序排列：`1.jpg, 2.jpg, 10.jpg`。
- 当前业务上限默认 10 张图；微信接口层可扩展到 20 张。

## 纯 API 工作方式

发布链路：

```text
本地图片
→ 微信永久素材接口 material/add_material
→ 获得每张图片 media_id
→ 微信草稿接口 draft/add
→ 创建 article_type=newspic 草稿
```

因此正常使用时不需要网页登录。运行电脑的公网 IP 需要加入公众号后台的 IP 白名单，公众号账号还必须具有素材和草稿接口权限。

## 安装与运行

要求 Python 3.11+。

Windows 直接运行：

```text
run-windows.cmd
```

也可以手动运行：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -e .
python -m wechat_draft_publisher
```

默认打开：

```text
http://127.0.0.1:8876
```

服务只允许本机同源访问。

## 首次配置

首次启动后，配置文件会创建在：

```text
%LOCALAPPDATA%\ZwmWechatDraftPublisher\settings.json
```

可参考 `config.example.json`。

推荐只在配置文件中保存 AppID，AppSecret 使用环境变量：

```powershell
setx WECHAT_MAIN_APP_SECRET "你的 AppSecret"
```

重新打开终端后生效。

## 测试模式

界面默认勾选“测试模式”。测试模式会完整执行：

- 扫描文件夹；
- 解析标题和正文；
- 检查图片；
- 计算内容哈希；
- 写入任务历史；
- 返回模拟草稿 ID。

但不会访问微信接口。完成真实公众号配置和 IP 白名单后，再取消勾选。

## 防重复与记录

SQLite 数据库存放在：

```text
%LOCALAPPDATA%\ZwmWechatDraftPublisher\draft-history.db
```

系统根据公众号账号、最终标题、正文和全部图片 SHA-256 生成任务哈希。相同内容成功创建过草稿时，默认阻止重复创建；界面可显式勾选“强制重复创建”。

## 运行测试

```bash
python -m unittest discover -s tests -v
```

当前测试覆盖：

- 单独帖子和作品集识别；
- TXT 标题/正文解析；
- 图片自然排序；
- 超长标题建议；
- 超过 1000 字只警告；
- newspic 草稿请求结构；
- 测试模式端到端入库。

## 与现有中控台的关系

本模块先作为独立本机页面运行，避免直接改动已经稳定的 Win32 素材投送主界面。后续集成时，现有中控台只需：

1. 增加“公众号草稿”入口；
2. 启动本模块本机服务；
3. 在现有窗口或系统浏览器打开 `http://127.0.0.1:8876`。

发布能力仍然完全走 API，不依赖网页自动化。
