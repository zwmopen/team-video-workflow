# “作品分享”快捷指令交付说明

状态：搭建清单已实现；iCloud 安装链接待实体 iPhone 导出；未验收

## 最终交付形式

实体 iPhone 完成搭建和逐项验收后，在“快捷指令”中选择“共享 → 拷贝 iCloud 链接”，得到：

```text
https://www.icloud.com/shortcuts/快捷指令ID
```

其他 iPhone 点链接后选择“获取快捷指令”即可安装。Windows 无法替苹果生成经过验证的可公开安装链接；必须在一台 iPhone、iPad 或 Mac 上完成最后一次导出。

## 第一版动作清单

快捷指令名称：`作品分享`

首次导入问题：`请选择固定作品总文件夹`，保存为文件夹变量 `作品根目录`。

每次运行：

1. 取得 `作品根目录`的内容，仅保留文件夹。
2. 排除 `_相册回收站`，其余只检查直接子文件夹。
3. 对每个子文件夹取得直接内容；同时有至少一张支持图片和一个 TXT 时加入作品列表。
4. 读取根目录 `_相册状态.json`；不存在则使用 `{"schemaVersion":1,"works":{}}`。
5. 先执行维护：把 `lastShareDate` 早于今天的作品移到 `_相册回收站`；把 `trashedDate` 已满 7 天的回收项删除。
6. 显示菜单，标题格式为 `未分享｜作品名` 或 `已打开分享 N 次｜作品名`；末尾增加 `查看回收站`。
7. 选中作品后，优先读取 `文案.txt`，否则按名称读取第一个 TXT。
8. 文案为空则停止并提示；否则复制到剪贴板。
9. 将对应记录的 `shareCount + 1`、`lastShareDate = 今天` 写回状态文件；保存失败时停止，不打开分享。
10. 提示 `文案已复制 · 第 N 次打开分享`。
11. 按文件名排序取得全部图片，执行系统“共享”动作。

回收站菜单：列出回收项；选中后先检查根目录是否存在同名文件夹。无冲突才移回根目录，清空 `lastShareDate` 和 `trashedDate`，保留 `shareCount`。

## 为什么暂时没有假链接或未签名文件

苹果在共享快捷指令时会验证副本。为了避免交付一个点不开、被系统判定为已修改或权限行为不一致的文件，本仓库不伪造 `.shortcut`，也不使用第三方签名站。连接实体 iPhone 后完成一次搭建、运行和 iCloud 导出即可得到正式安装地址。

完整状态、安全和错误规则见仓库设计文档：`docs/superpowers/specs/2026-07-19-ios-shortcut-work-share-design.md`。
