# 相册投送 V0.3.1：图标与设备备注

日期：2026-07-18

## 本轮目标

- Windows 和 Android 都补上正式应用图标，避免继续使用系统默认图标。
- Windows 端支持给手机做本机备注，方便多台手机区分。
- 显示优先级遵循：电脑本机备注 > 手机端广播名称。

## 设计选择

图标采用“相册卡片 + 绿色投送箭头”的方向：看起来像相册工具，但不伪装系统相册包名，也不改变分享来源的真实应用身份。

Windows 端备注只保存在本机：

```text
%LOCALAPPDATA%/ZwmDeviceShareHub/device-remarks.tsv
```

这样不会改手机端设置，也不会污染仓库。手机端自己设置的名称仍会通过局域网广播传给电脑；电脑端有备注时，卡片主标题显示备注，副标题保留手机名称、型号和 IP。

## V0.3.3 补充：华为文件夹扫描兼容

华为 ELE-AL00 实体机上确认当前 0.3.2 已保存系统文件夹授权：

```text
content://com.android.providers.downloads.documents/tree/msd%3A519
```

0.3.2 日志显示它能识别并导入 1 个作品，但旧逻辑存在一个容易误判的问题：如果所选目录本身包含图片和 TXT，就会被当成一个作品并停止继续扫描，下面更多作品子文件夹可能不会显示。

0.3.3 改为：

- 递归优先：先扫描子文件夹。
- 如果子文件夹里没有作品，才把当前文件夹当成单个作品。
- 如果当前文件夹像“聚合目录”，并且子文件夹已经识别到作品，则跳过上层聚合目录，避免把一大坨内容合并成一个作品。
- 诊断日志增加 `scannedFolders` 和 `aggregateFolders`，方便定位是权限、格式、层级还是重复导入问题。
- 当没有识别到作品时，界面提示改为“没识别到作品：请选择包含‘图片 + TXT’的作品文件夹”。

验收状态：

- 华为 ELE-AL00 已确认连接、已确认 0.3.2 能保存文件夹授权并导入至少 1 个作品。
- 0.3.3 扫描策略完成后等待 CI 产包并安装到华为实体机操作确认。

## V0.3.4 补充：固定 Android 开发安装签名

华为 ELE-AL00 上验证发现：旧 0.3.2 无法直接覆盖安装 CI 产出的 0.3.3，系统报错：

```text
INSTALL_FAILED_UPDATE_INCOMPATIBLE: Package com.zwm.gallery signatures do not match previously installed version
```

原因是此前 GitHub Actions 使用临时 debug 签名，每次构建出的 APK 签名可能不同，导致手机系统把它们当成“同包名但不同作者”的应用，禁止覆盖升级。

0.3.4 开始，Android debug APK 使用项目内固定开发签名：

```text
tools/device-share-hub/android/app/signing/gallery-debug.jks
SHA-256: CA:C5:46:53:FD:FD:BD:19:E0:D9:95:2F:EC:A7:0E:9B:2A:05:30:CE:66:76:EB:17:A3:EC:24:A5:6B:E1:84:8B
```

注意：

- 这是方便内部测试和多台手机覆盖升级的开发签名，不是正式上架签名。
- 已安装旧临时签名包的手机，第一次升级到 0.3.4 仍需卸载旧版后安装；这会清除 App 私有设置和已导入列表，但不会删除手机 Download/Lark 里的原始作品文件夹。
- 安装 0.3.4 之后，后续 0.3.5、0.3.6 等同一固定签名包即可覆盖升级。

验收状态：

- 固定签名配置已实现，等待 CI 产包。
- 华为 ELE-AL00 上 0.3.2 到 0.3.4 的首次迁移需卸载旧版后安装，完成前不宣称迁移测试通过。

## V0.3.6 补充：授权目录内 ZIP 自动导入

华为 ELE-AL00 上安装 0.3.5 后，扫描明细显示：

```text
d0:519 dirs=3 files=5 img=0 txt=0
d1:521 dirs=0 files=0 img=0 txt=0
d1:1003 dirs=1 files=0 img=0 txt=0
d2:1508 dirs=0 files=13 img=12 txt=1 cap=文案_20260617_173034.txt
d1:1374 dirs=0 files=0 img=0 txt=0
```

结论：鸿蒙系统授权目录里，App 实际只看到了一个有效作品文件夹；根目录还有 5 个普通文件，但旧版本只扫描文件夹，因此如果这些文件是 Lark/Download 里的 ZIP 合集包，就不会被导入。

0.3.6 增加：

- 在授权目录递归扫描时，同时收集 `.zip` 压缩包。
- 自动解析 ZIP 内部的作品文件夹，沿用现有“图片 + TXT”规则导入。
- 已导入过的 ZIP 作品再次扫描会跳过，不再因为重复 ID 报错。
- 日志增加 `archives`、`archiveImportedWorks`、`archiveErrors`。

验收状态：

- ZIP 自动导入已实现，等待 CI 产包并覆盖安装到华为 ELE-AL00 后实体扫描验收。

## V0.3.7 补充：鸿蒙隐藏/疑似目录兼容

用户实体机排查发现，问题可能出在点开头的隐藏目录。华为/鸿蒙或 Lark 文件目录通过系统文档接口返回时，某些隐藏目录可能没有标准 `vnd.android.document/directory` 类型，导致旧逻辑把它放进普通文件列表，不会继续递归。

0.3.7 调整：

- 不再只相信系统返回的目录 MIME。
- 对点开头、无扩展名、类型为空或 `application/octet-stream` 的条目，尝试按目录继续扫描。
- 如果疑似目录实际打不开，会在诊断日志记录 `dir?:目录名 error=...`，不影响其它目录。
- 扫描明细日志使用真实显示名，不再只显示系统 documentId 末尾数字，方便和手机文件管理里的名称对上。

验收状态：

- 隐藏/疑似目录兼容已实现，等待 CI 产包并覆盖安装到华为 ELE-AL00 后实体扫描验收。

## V0.3.8 补充：作品文件夹不读取压缩包

手机端“设置作品文件夹”的职责收窄为：递归识别目录中直接包含“图片 + TXT”的作品子文件夹。

- 授权目录中的 ZIP 和其他压缩包一律忽略，不复制、不解压、不导入。
- ZIP 合集仅通过 Windows 端拖入；由电脑端解析并通过现有局域网投送流程发送。
- 扫描诊断日志移除压缩包数量和压缩包导入结果，避免产生错误暗示。

验收状态：

- 华为 ELE-AL00 已覆盖安装 0.3.8 并刷新授权目录：识别 3 个“图片 + TXT”作品文件夹，日志不再出现压缩包扫描或导入字段；“作品文件夹忽略压缩包”已完成实体机验收。
