# 远程在线通道设计

## 能否做到

可以。手机使用流量、连接异地 Wi‑Fi，甚至电脑与手机不在同一城市时，电脑面板仍可显示手机在线并完成拖拽投送。

## 推荐架构：双通道，而不是直接暴露电脑端口

### 局域网通道

- Windows 通过 UDP 自动发现手机。
- 文件由电脑直接传到手机。
- 不经过云端，速度最快。

### 云端中继通道

- Windows 和安卓都主动建立出站 HTTPS / WebSocket 连接。
- 云端维护设备在线状态和任务通知。
- 文件由电脑上传到临时对象存储，手机收到命令后下载。
- 下载完成、SHA-256 校验通过后删除云端临时文件。

推荐 Cloudflare 组合：

- Workers：认证、任务 API、临时下载授权。
- Durable Objects：工作区内设备在线状态和 WebSocket 会话。
- R2：图片和视频的短期中转存储。

这种方式不需要公网 IP、不需要路由器端口映射，也不需要电脑开启可被互联网扫描的入站端口。

## “绑死”但不让用户手动配对

第一次电脑与手机在同一局域网出现时：

1. Windows 创建一个工作区 ID 和高强度工作区密钥。
2. 通过当前局域网直连自动写入手机。
3. 手机保存自己的设备私钥和工作区凭据。
4. 之后两端在任何网络下都用该身份登录中继。

这个过程可完全自动完成，界面上不出现地址、令牌或配对码。设备列表按稳定 `deviceId` 合并，因此从 Wi‑Fi 切到手机流量时，同一张设备卡片只会从“局域网”切换为“云端”。

## 传输策略

```text
发现局域网直连可用？
├─ 是：电脑 → 手机直传
└─ 否：电脑 → R2 临时文件 → 手机下载
```

优先直传，云端只作为异地和移动网络兜底。

## 安全要求

远程通道不能沿用 V2 的“局域网无鉴权”模式，至少需要：

- 每个工作区独立密钥；
- 每台设备独立身份；
- TLS；
- 短时有效的上传/下载授权；
- 文件 SHA-256 校验；
- 临时文件自动过期；
- 支持从电脑端移除丢失的手机。

## 为什么不默认使用 Cloudflare Tunnel

命名 Tunnel 可以把电脑服务暴露到公网，但仍需处理固定域名、凭据、在线状态、文件权限和电脑断线恢复。对于“多手机在线列表 + 拖拽投送”，双方都主动连接中继更稳定，也更容易自动切换局域网与移动网络。
