# 相册投送 V3：设计与实现存档

日期：2026-07-18  
V2 基线：`acdf93979ca3ed3f562b6753fe3cb93ae565dd68`

## 第一性原理

用户真正要完成的动作只有一个：选定一条作品，进入目标平台发布。软件应承担文件传输、解压、识别、文案复制、图片选择和系统分享准备；用户只保留平台选择、粘贴/确认和最终发布。

因此默认流程是：

```text
电脑拖入 ZIP 或文件夹
→ 电脑自动发现手机并传送
→ 手机自动展开和识别作品
→ 用户点一个作品
→ 自动复制 TXT + 带上全部图片 + 打开系统分享
```

不引入 IP、配对码、命令行、Node.js 网页面板、管理员权限、Root、无障碍、自动点击或自动发布。

## 手机信息结构

首页只有四类对象：

1. 当前作品文件夹和“设置路径”；
2. 作品页操作：“刷新作品 / 回收站”；
3. 两列作品卡片；
4. 接收状态和诊断入口。

进入回收站后，操作切换为“返回作品 / 清空回收站”。清空必须二次确认；回收站为空时按钮禁用。作品页不显示清空操作，避免把不同上下文混在一起。

作品卡片直接使用源文件夹名称。未分享卡片为白色和绿色主按钮；已打开分享的卡片整块变灰，显示 `✓ 已打开分享`，仍可再次分享。

## 作品判定

- 从 ZIP 或授权目录递归扫描。
- 当前文件夹的直接内容同时有至少一张支持图片和一个 TXT，才是一个作品。
- 图片支持 JPG/JPEG/PNG/WEBP/HEIC/HEIF。
- 优先 `文案.txt`，否则自然排序取第一个 TXT。
- 图片自然排序，`2.jpg` 在 `10.jpg` 之前。
- ZIP 拒绝绝对路径、盘符路径和 `..` 越界，并限制作品数、图片数与单文件大小。

## 存储模型

App 私有目录是分享时的权威作品库：

```text
files/work-library/
├─ active/<work-id>/
│  ├─ meta.properties
│  └─ images...
└─ trash/<work-id>/
```

选择 `Download/Lark` 或其他目录后，App 保存 Android SAF 持久权限：

- 打开 App 或点“刷新作品”时递归导入目录内作品；
- 电脑传入 ZIP/文件夹时，先提交 App 私有库，再尽力把识别后的文件夹同步一份到授权目录；
- 外部目录不可写时记录诊断，但不回滚已经安全接收的私有作品。

从分享目标返回只记录“已打开分享”，因为 Android 不提供目标平台是否完成发布的可靠结果。下一自然日把该作品移入 App 回收站；7 天后清理。用户可恢复或在回收站内确认后立即清空。

## Windows 实现

Windows 面板保持纯 Win32 C++：

- UDP 自动发现同一 Wi‑Fi 手机；
- 拖 ZIP 直接传；
- 拖文件夹时本地生成 UTF‑8、无压缩临时 ZIP，保留相对目录结构，传完清理；
- SHA-256 校验；
- 显示进度条、百分比、已传/总量和速度；
- 支持取消并通知手机清理未完成任务；
- 诊断日志写入 `%LOCALAPPDATA%/ZwmDeviceShareHub/diagnostics.log`。

## 身份与安全边界

- Android 显示名：`相册`
- 包名：`com.zwm.gallery`
- Provider：`com.zwm.gallery.files`

应用使用标准 Android 分享 Intent，不伪装系统相册包名，不隐藏调用来源，不承诺规避抖音、小红书等平台风控。
