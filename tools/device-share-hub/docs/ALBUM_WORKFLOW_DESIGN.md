# 相册作品库工作流设计

日期：2026-07-18

状态：已获用户口头批准，待书面复核

基线：`acdf93979ca3ed3f562b6753fe3cb93ae565dd68`

## 目标

把现有“电脑逐批传图片、手机立即分享”升级为作品库：电脑可以拖入 ZIP 或单个作品目录，手机按作品文件夹展示；用户点一次作品即可复制 TXT 文案、选择全部图片并打开安卓系统分享面板。

产品不使用 ADB、管理员权限、Root、无障碍、自动点击或自动发布。ADB 仅允许用于本次开发机上的安装与实体机测试，不进入用户工作流。

## 产品名称与身份

- Android 显示名称：`相册`
- Android 包名：`com.zwm.gallery`
- 文件分享 Provider：`com.zwm.gallery.files`
- Windows 显示名称继续使用：`素材投送中控`
- 新包先与旧包 `com.zwm.deviceshare` 共存；新包实体机验收通过后再移除旧包。

## 素材来源

### 电脑直传（默认最短路径）

Windows 支持把以下内容拖到手机卡片：

- 一个 ZIP；
- 一个单独作品目录；
- 多张图片。

为避免把结构复杂的大目录误判、误传，Windows 不直接接收带嵌套子目录的聚合文件夹。作品合集使用 ZIP；单独作品目录必须在直接层同时包含图片和 TXT。

ZIP 在电脑端安全解析，不要求手机端下载和手工解压。扫描完成后先显示识别出的作品数、图片数、总大小，再开始发送。

### 手机目录（复用现有素材）

首次使用时通过安卓系统目录选择器选择 `Download/Lark` 或实际的飞书素材目录。应用保存系统授予的持久目录权限，之后自动读取该目录的所有子目录。

由于 Android 11 及以上禁止应用通过目录树选择器获得整个 `Download` 根目录，产品不申请全盘文件权限，不使用“所有文件访问权限”。若不同飞书版本的目录名不同，以用户首次真实选择的目录为准，不硬编码大小写或固定路径。

## 作品识别规则

从选定目录或 ZIP 根目录递归向下扫描：

1. 仅检查当前目录的直接文件；
2. 当前目录至少包含一张支持的图片，并至少包含一个 `.txt`，则认定为一条作品；
3. 仅含子目录、不满足作品条件的目录继续向下扫描；
4. 父目录不会因为后代目录有图片和 TXT 而被重复识别为作品；
5. 支持图片：`.jpg`、`.jpeg`、`.png`、`.webp`、`.heic`、`.heif`；
6. 文案优先级：`文案.txt`，其次是自然排序后的第一个 `.txt`；
7. 存在多个 TXT 时仍可导入，但作品卡片显示“多个文案文件，已使用：文件名”；
8. 图片按文件名自然排序；隐藏文件、系统文件、回收站目录和不支持的文件忽略；
9. 单条作品最多 100 个媒体文件；超限、空文案、损坏 ZIP、危险 ZIP 路径或空间不足必须显示明确错误，不静默跳过。

## Android“相册”界面

首页保持单页、少按钮：

- 顶部：当前素材目录、刷新、选择/更换目录、回收站；
- 主区：作品卡片列表；
- 卡片：首图缩略图、文件夹名、图片数量、文案状态、来源、分享状态；
- 状态：`未分享`、`已打开分享 N 次`、`已移入回收站`、`导入异常`；
- 诊断信息保留一键复制入口。

点击作品卡片执行：

1. 读取选定 TXT；
2. 写入系统剪贴板；
3. 明确提示“文案复制成功”；
4. 组装该作品全部图片的 `ACTION_SEND_MULTIPLE`；
5. 使用临时 URI 读取权限打开安卓系统分享面板；
6. 用户从分享目标返回后标记为“已打开分享”。

Android 无法可靠获知目标平台是否最终发布成功，因此界面不宣称“发布成功”。用户可撤销分享标记或重新分享。

## 分享来源与风控边界

默认保持正规的安卓系统分享，不伪装系统相册、不隐藏调用包、不修改目标平台、不模拟点击。平台可能识别调用来源，产品不承诺规避平台风控。

后续如有平台兼容问题，可增加真正写入 `MediaStore` 的“保存到系统相册”模式，但不作为本阶段默认路径。

## 次日清理与回收站

- 作品从分享目标返回时记录本地日期和时间；
- 到下一个本地日历日后，作品在 App/接收服务下一次唤醒时移入回收站；
- 系统定时任务作为补充，但不承诺凌晨零点精确执行；
- 回收站保留 7 个完整日历日，期间可恢复；
- 到期后永久删除；
- 电脑直传的 App 私有作品使用同文件系统移动；
- Lark 外部目录在所选目录内创建并使用 `相册回收站`；优先使用文档提供方的安全移动能力；
- 如果外部提供方不支持安全移动或写权限丢失，则不删除源文件，保留作品并显示可诊断错误；
- 所有删除前必须确认目标属于当前作品目录或回收站，禁止越界删除。

## Windows 面板

- 保留同一 Wi-Fi 自动发现，不增加 IP、配对码或命令行；
- 支持拖入 ZIP、目录和原有多文件；
- 发送前显示识别结果；
- 传输时显示真实总进度条、百分比、已传/总大小、速度、当前作品和当前文件；
- 支持取消，取消后通知手机清理未完成批次；
- 显示可执行的中文错误提示；
- 保留“打开诊断日志”；
- 使用静态 MSVC 运行库构建真正便携 EXE；
- 高 DPI、窗口缩放、中文截断和最小窗口尺寸必须验证。

## 协议与存储

在 V2 上做向后兼容扩展：

- V2 单批媒体继续工作；
- 新批次包含作品清单：作品 ID、目录名、文案文件、媒体文件、相对顺序和校验值；
- 文件继续逐个流式传输并做 SHA-256 校验；
- 手机只在整个清单与所有文件校验完成后原子提交作品库；
- 中断、校验失败或取消不得生成半条可分享作品；
- 作品状态和分享时间单独保存，不能依赖文件名猜测。

## 错误处理

必须区分并记录：未授权目录、授权失效、ZIP 损坏、路径越界、无有效作品、多个 TXT、文件超限、磁盘不足、网络中断、校验失败、目标目录不可写、回收站移动失败和永久删除失败。

用户提示使用普通中文，并给出下一步操作；诊断日志记录时间、设备、任务、作品、文件、阶段、耗时和系统错误，不记录文案正文。

## 验收标准

自动化检查：

- 作品识别规则、自然排序、文案优先级、嵌套目录、危险 ZIP 路径；
- 批次清单解析、原子提交、取消与校验失败；
- 次日判定、7 日回收站、恢复和越界删除保护；
- Android 构建与 Lint；
- Windows x64 静态运行库构建。

红米实体机验收：

- 新包安装、首次选择 `Download/Lark` 并在重启后保持权限；
- 递归识别现有作品合集；
- 点击作品后出现“文案复制成功”，剪贴板内容正确，全部图片进入系统分享面板；
- 返回后显示“已打开分享”；
- 模拟跨日后移入回收站、恢复、7 日到期清理；
- Windows 自动发现、ZIP 整批发送、真实进度条、取消、断网和错误日志；
- 新版通过前不删除旧包。

所有未在实体红米上执行的项目不得宣称测试通过，应直接记录尚未操作的项目。
