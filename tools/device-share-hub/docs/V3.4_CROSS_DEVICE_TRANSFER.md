# V3.4 跨设备传送设计与开发沉淀

## 目标

把三端传送压缩成一个一致动作：打开“传送”→ 选择自动发现的设备 → 选择文件或文件夹。用户不需要理解地址、端口、配对或命令行。

## 三端职责

- Windows：保留拖放发送，并新增文件/文件夹选择按钮；同时开放接收端，收到内容写入 `下载/相册收件箱`。
- Android：前台服务继续接收和广播在线状态；主界面右下角进入传送页，可向 Windows、iPhone 或另一台 Android 发送。
- iPhone：仅在应用前台运行局域网服务，降低后台占用并遵守 iOS 限制；主界面右下角进入传送页。

所有设备继续使用 Protocol V2：UDP 45834 自动发现、HTTP 45833 传输、任务创建、逐文件 SHA-256 校验、提交或取消。V3.4 与旧电脑发手机流程保持兼容。

## 文件夹规则

文件夹发送方先生成名称以 `album-folder-` 开头的 ZIP32 存储包，保留相对路径。接收方只自动展开这种内部文件夹包；普通 ZIP 当作普通文件，避免擅自改变用户文件。路径越界、单文件超过 4GB、文件数超过 10000 会被拒绝并显示原因。

## 发现与离线

设备每约 2.5 秒广播一次在线消息，列表只保留最近 9 秒出现的设备。Windows 的手动刷新会立即清空旧设备并重新探测。iPhone 不后台常驻，因此锁屏、切到后台或被系统挂起后会从列表自然消失。

## 安全边界

- 仅用于可信的同一 Wi‑Fi，不暴露到公网；
- 不伪装其他应用包名，不模拟相册来源，不注入虚假 EXIF；
- 不要求 Root、ADB、管理员、无障碍、配对码或手动 IP；
- 文件名被清理，文件内容校验 SHA-256，文件夹展开拒绝绝对路径和 `..`；
- 诊断记录设备显示名、阶段与错误，不记录 Apple ID、GitHub token、iPhone UDID 或文件正文。

## 兼容与验证规则

同一安装包面向 Android 8+、iOS 12+ 和 Windows 10/11，不为某一台手机另做分叉。云端编译、模拟器测试与实体机业务验证分开记录；实体设备未实际完成的方向不得写成真机通过。

## 本次踩坑与复用

1. Windows 图标资源加入 CMake 时，不能同时在 RC 和链接器中重复嵌入 manifest；图标放 RC，manifest 用链接器输入。
2. iOS 的文件夹 ZIP 必须使用存储方法（method 0），才能与内置安全展开器兼容；普通压缩算法不能直接假设三端都可展开。
3. iPhone 的服务只在前台可靠；不要用高频后台唤醒换取“看起来在线”。
4. Android SAF 和 iOS security-scoped URL 都需要在授权窗口内读取或复制到应用缓存，再开始长传输。
5. GitHub Actions 私有仓库额度按仓库所有者计算。主源码仍在 `zwmopen`，耗时三端构建可同步到 `rpgzwm/team-video-workflow-build` 执行；OAuth 凭据只存 Windows 密钥库。
