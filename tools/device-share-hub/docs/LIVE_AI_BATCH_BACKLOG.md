# 图转 Live · AI 批量动态生成备用技术路线

> 记录日期：2026-11-27
> 状态：**仅开发灵感 / 技术候选 / 暂不排期**。
> 归属：「文件收发中控 / 团队工作相册」中的「实况图加工工坊」。
> 决策：继续使用现有的纯本地轻微缩放、自然手持微动等方案；**不要因本清单自动修改产品、接入第三方 API、购买额度、构建或发布**。

## 1. 用户真实需求

- 把**单张静态团建实拍照片**变为“真的会动”的短动态素材，而不只是机械放大：如人物轻微转头、眨眼、衣物/树叶摆动、水面自然流动。
- 将来可以**批量**处理一整套照片，而不是逐张手工上传。
- 优先：原场地、建筑结构、人物比例、空间关系真实；其次：清晰度与原图接近、稳定出片、处理成本低、可复用。
- 最终可能需要 MP4、GIF、Apple Live Photo；Android Motion Photo 是另一种格式，须独立验证。**MP4/GIF、JPG+MOV 文件对，不自动等于设备或小红书已识别的 Live Photo**。
- 用户明确要求这类想法作为 **GitHub 开发候选** 留存，**不是个人长期记忆，也不是当前开发指令**。

## 2. 当前主路线（保持）

当前产品已有纯本地的实况图微动能力，含手机端“分享时静图自动转实况”方向；源仓库 README 记录了工坊、轻微微动预设和部分真机/构建状态。

- 主路线：原图 → 本地确定性微缩放/平移/自然手持微动 → 短视频及按设备要求封装。
- 优势：不消耗生成积分、不依赖外部 AI 服务、成本和行为可预测，便于批量运行。
- 局限：画面整体在动，但人物肢体、树叶、水流并非真正发生语义运动。
- 不因新增 AI 方向撤销或替换此主路线。

## 3. 未来 AI 语义动态候选

| 候选 | 技术路径 | 可探索的价值 | 限制 / 实施前必须核验 |
| --- | --- | --- | --- |
| **ComfyUI + Wan 2.2** | 本地开源图生视频工作流 | 本地批量队列、理论上不按张计费、便于控制中间产物 | 需要显卡资源和模型部署；“免费”不等于零设备成本；需实测速度、显存、场景稳定性及模型许可 |
| **即梦 / Dreamina** | 在线图生视频 | 上手快、适合少量真实动效对比 | 免费额度/水印/可用模型/自动化权限随产品和地区变化；不默认可无限批量 |
| **PixVerse** | 在线图生视频 | 作为另一组动效与成本对照样本 | 免费积分与限流须重新核实；批量 API 不一定免费 |
| **可灵 AI** | 在线图生视频 | 人物动作、镜头运动效果候选 | 积分、分辨率、水印、官方 API 费用/权限待核验 |
| **Vidu** | 在线图生视频 | 轻量动态、原比例照片的候选 | 当前免费配额、比例、生成稳定性与自动化授权待实测 |
| **Google Flow** | 在线图生视频 | 对接已有 Flow 实验工作流 | 可能消耗积分；留待明确排期后评估，避免与现有独立 Skill 重复实现 |

**现阶段没有任何一家被验证为“长期无限免费 + 可用官方批量接口 + 高质量出片”。** 不能把每日赠送积分写成稳定免费产能，也不能依靠多账号绕过额度或非授权批量抓取。

## 4. 可能的未来产品形态（非实施任务）

```text
选一套图片（保留原片只读）
  ├─ 默认 A：本地微动 → 低成本 MP4 → 按需封装 Live
  └─ 可选 B：AI 真实动效 → 批量排队 → MP4 → 按需封装 Live
                                        ↓
                    逐张质量检查 / 失败重试 / 结果回写
```

未来若要开发，再按实际设备和能力选用：电脑本地 GPU 任务队列、远端正式 API、或通过既有电脑服务转交任务。手机端可以**直接选择、提交、查看进度、取回结果**，不应假设 AI 大模型一定能在手机本机运行。

## 5. 技术验收门槛（未来再执行）

1. **场地保真**：楼体、房间格局、道路、设施、人数不凭空变化；人物面容/手指/衣服不明显畸变；绝不将 AI 虚构画面冒充实拍。
2. **清晰度**：原图永不覆盖，记录原图尺寸与编码；比较输出帧清晰度、压缩损失和静帧画质，必要时单独保留原图作为静态主帧。
3. **动态真实感**：小幅、自然、连续的动作优先；避免大幅扭曲、抽帧闪动、突然切景。实拍场地不适合夸张运动。
4. **批量可靠性**：每图独立任务 ID、输入/输出一一映射、可取消/断点续跑、失败单独重试、失败不影响其他图片、逐张记录耗时/积分/错误。
5. **格式验证**：输出 MP4 ≠ Live；iOS 的真实 Live Photo 导入与播放、Android Motion Photo、目标平台上传识别，必须使用设备和平台做 E2E 验收。
6. **成本决策**：统一用“每张可用成片的全部成本”评估：积分/云 GPU + 本地算力电耗 + 失败重试 + 人工挑片 + 时间成本。不得凭“注册免费”判断可批量商用。
7. **授权与风控**：确认模型许可证、照片授权、第三方服务条款与可用 API；不得自动购买或上传未授权素材。

## 6. 启动条件

只有用户之后明确提出“开始开发 / 实测 AI 动图批量路线”时再：
- 重新查询实时价格、积分、服务条款与 API 文档；
- 按设备显卡条件筛选可落地路线；
- 取 **3–5 张有权使用的团建实拍样本** 做一致性 A/B 测试（人像、建筑、室内、草木、水面）；
- 比较原图画质、失真率、速度、单张可用成本；
- 再决定是否写成需求、拆分任务、接入和发布。
