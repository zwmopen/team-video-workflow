# Android 0.6.20 双通道更新候选

## 目标

手机打开后主动把版本、版本码、作品总数、分类库存和更新能力告诉电脑。电脑发现手机版本较低时，优先保持手机自己的 GitHub 更新；GitHub 检查失败时，再从电脑的本地 APK 缓存走局域网更新包投送。

源码推送后由 GitHub Actions 在云端构建 Android APK，并在构建、测试、Lint 都通过后发布版本化 APK、SHA-256 和 `latest.json`。电脑不做定时轮询；只有发现已连接的低版本手机且本地没有候选包时，才按需取回已发布 APK 作为局域网备用包。

## 版本

- Android：`0.6.20`
- versionCode：`58`
- 更新能力：`apk-push-v1`
- Windows：`4.3.6`
- 状态：源码候选，尚未宣称正式发布或完成 VIVO 真机验收。

## 安全边界

- 电脑只缓存带可识别版本号的 APK，并保留旧版本文件作为回退材料。
- 自动推送只走 Wi-Fi LAN V2，不复用作品去重、移动、归档和自动补货账本。
- 手机收到 APK 后继续校验 SHA-256、包名、版本码和签名；系统安装仍由用户确认。
- 电脑只在收到版本和更新能力后触发；旧客户端或版本未知时不盲推。
- 按需取回失败时保留已有缓存；同一手机、同一版本已自动投送过后，即使电脑重启也不自动重复投送。

## 必须验收

1. Android 单元测试、Release 构建和 Release Lint。
2. Windows 原生编译与 CTest。
3. VIVO 打开应用后，电脑卡片显示版本、总作品数和分类库存。
4. 电脑选择带版本号的 APK 后，确认缓存出现在 `%LOCALAPPDATA%\\ZwmDeviceShareHub\\mobile-updates`。
5. 手机版本较低时只收到一次更新包；手机不安装时电脑进入冷却，不重复推送。
6. 手机安装后重新上线，电脑读到新版本，后续不再触发同一版本更新。
