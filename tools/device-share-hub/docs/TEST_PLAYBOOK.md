- 让 P2P 在 20 秒内无法建连或中途断网：Windows 必须自动切换 HTTPS 中继；手机收到后仍要完成大小/SHA-256、作品库导入和 ACK，不能出现重复作品。
- 伪造错误哈希、未知对象序号、空洞偏移或超 48 KiB 分片：手机必须拒绝并清理缓存，电脑不得把失败记录为成功。
- 停止/重启手机接收服务后检查缓存目录和后台轮询线程；旧 USB、同 Wi-Fi V2 和普通 HTTPS 中继路径各至少回归一次。
- CI 编译通过只证明 SDK/API 接入正确；没有真实 Android/iPhone 实际收发前，交付记录必须标明“P2P 实体业务待验收”。

### 线上 Cloudflare E2E 门禁

- `Device Share Hub` workflow 的 `remote-relay-live-e2e` job 直接访问正式 Worker，不使用本地 Wrangler 模拟服务。
- 当前证据：run `32568228480` / job `97019921822` 通过；health、工作区登记、双端会话、在线心跳、P2P offer/answer/close、R2 上传、commit、收件箱、下载 SHA-256、ACK 和 R2 删除共 14 个阶段全部成功。
- 线上 E2E 只证明服务端和控制面/中继数据链路可用，不能替代实体手机的 WebRTC DataChannel、作品库写入、失败回退、权限和厂商安全扫描。

## 发布前最小检查

### 1. 自动构建

- Windows：Release x64 编译，EXE 可启动，图标和 manifest 正常；
- Android：单元测试、`assembleRelease`、Release Lint；解包核对 `debuggable` 未启用，签名证书与已安装正式链一致；
- iOS：XcodeGen、测试目标编译/运行、iPhoneOS 构建、IPA 结构校验；
- 通用：密钥扫描、版本号和产物命名一致。

### 2. 升级与数据保持

- Android 使用原 applicationId/签名覆盖安装，确认目录授权、作品和分享次数仍在；
- iPhone 侧载覆盖安装，确认所选目录 bookmark、设备名称和作品状态仍在；
- Windows 覆盖 EXE 前退出旧进程，覆盖后比较构建产物与桌面文件 SHA-256。

### 3. 三端发现

1. 三端连接同一非访客 Wi-Fi并打开应用；
2. Windows 不显示自己，显示两台手机；
3. Android 显示 Windows 与 iPhone；
4. iPhone 显示 Windows 与 Android；
5. 等待 20 秒后再次检查；
6. 关闭一端或让 iPhone 进入后台，15 秒后应自然离线；手动刷新应立即清理旧列表并重新探测。
7. Android 保持 App 进程运行，断开再恢复 Wi-Fi；不得重开 App。恢复后双向重新发现，并等待超过 15 秒再查一次。诊断应能区分临时网络错误、自动重试和恢复。

### 4. 接收器无污染检查

对目标端执行：

1. `GET /v2/info`，确认协议、版本、在线状态；
2. 创建一个 1 文件任务；
3. 上传小文件并提供 SHA-256；
4. 调用 cancel，不 commit；
5. 状态应依次为 200、201、200、200，用户作品目录不新增文件。

这套方法适合快速检查“设备能发现但上传 timeout”。正式发布前仍要至少选择一个方向执行完整 commit 并核对实际落点。

### 5. 文件与文件夹传送

- 普通文件保持名称和字节；
- 文件夹打包后保留相对目录；
- 普通 ZIP 不擅自展开，`album-folder-*.zip` 才按文件夹包展开；
- 接收端拒绝绝对路径、`..`、超限文件和错误 SHA-256；
- Windows 显示百分比、已传/总量、速度、完成或可行动错误；取消后不留下半成品。
- Android 传送方式分别验证自动、USB、Wi‑Fi并确认选择会保留。USB 模式未开启系统 USB 网络共享时必须显示设置入口；开启后电脑条目标记 `USB`，不能把普通 Wi‑Fi 误标。
- USB 网络共享建立后分别执行手机→电脑和电脑→手机测试文件，核对文件名、字节与 SHA-256；普通 MTP 只计电脑→手机，不把它误报成手机可主动访问的双向通道。
- Windows 中控运行且至少两台设备在线时，资源管理器“右键 → 发送到 → 相册在线设备”应只列出当前可用设备；分别发送单文件、多文件和文件夹，确认只唤起现有单实例窗口并显示真实进度。
- 在会抑制 Wi‑Fi 广播回复的路由器上，确认原生主动探测仍能发现 `/v2/info` 在线设备。关闭一台 Wi‑Fi-only 设备并等待 35 秒以上，其快捷方式应消失；USB 仍可用的设备必须保留。退出中控后“相册在线设备”菜单自动移除，用户原有“发送到”项目不得改变。
- 快捷方式目标设备在点击后瞬间离线时，应在 20 秒内给出可行动提示，不创建半成品；上一批仍在传送时拒绝第二批并保留原任务。

### 6. 作品扫描与分享

- 同目录直接包含至少一张支持图片与一个 TXT 才是作品；
- 覆盖普通目录、点号作品、空目录、作品包嵌套、多个 TXT、自然排序和回收站目录；
- 数字只显示作品数量，不显示遍历目录数；
- 点击后立即记一次，再准备文案和图片并打开系统分享面板；取消、回调缺失、Activity 恢复都不得漏记或重复记账；
- Android/HarmonyOS 检查 SAF 与兼容通道不会重复导入。
- Android 10+ 在小米/VIVO 分别检查主应用与应用分身：单图、多图都应进入目标编辑页，不能只确认分享面板出现；诊断日志应记录 `strategy=media_store`。
- HarmonyOS / EMUI 需覆盖系统选择器“结果先返回、目标回调稍后到达”的顺序：目标真实选中后次数只加 1；直接取消选择器不增加次数；不得为了修华为破坏 VIVO 分身冷启动等待。
- 分享临时副本可供目标读取，生成满 1 小时后清理；原作品、分享次数和回收站数量不得因此变化。

### 7. 回收站

- 默认从首次点击分享起满 1 小时进入真实回收站；设置 1～10 小时边界分别验证；
- 原目录不再显示该作品；恢复后回到原位置；
- 清空后系统文件管理器也不再存在真实文件；
- 默认首次分享满 1 小时后从文件管理中彻底删除；允许与回收时间相同，且删除时间不得早于回收时间。
- 升级前只有日期的记录使用北京时间迁移：昨天及更早内容应在刷新时按到期处理；当天内容以升级时刻为新锚点，满 1 小时前不得移动或删除；重复刷新不得重置这 1 小时。
- iPhone 回收站中没有状态记录的旧文件夹以升级时刻为锚点，满 1 小时后删除；不得因为无法推断旧时间而在首次启动瞬间删除。
- 根目录同时存在“相册回收站”“相册回收站 (1)”和“_相册回收站 (2)”时，首页和作品文件夹选择器均不得把其中内容显示为作品；“相册回收站教程”“相册回收站 (A)”仍按普通目录参与判定。
- 长按普通作品后所有卡片出现复选框；连续勾选至少两项，顶部数量和右下角垃圾桶同步。反选或按返回键可取消。确认后真实文件夹进入“相册回收站”，首页消失、分享次数保留；批量部分失败时成功项与失败项提示和状态必须对应。

### 8. 更新体验

- 手机打开后应在在线信标和 `/v2/info` 中上报 `appVersion`、`versionCode`、总作品数、分类库存和 `apk-push-v1` 能力；电脑设备卡应能显示手机版本及精准/泛库存。
- 电脑选择一个带版本号的 APK 发送时，应把它复制到 `%LOCALAPPDATA%\\ZwmDeviceShareHub\\mobile-updates` 作为本地更新缓存；缓存目录保留可回退的旧版本，不进入作品传输历史。
- 开启电脑端自动更新且缓存为空时，让一台具备更新能力的低版本手机上线；确认电脑只在这个触发点按需取回已发布 APK，并校验 `zwmopen/gallery-updates` 地址和 SHA-256，不做定时轮询，也不会覆盖更高的本地候选。
- 手机版本低于本地缓存版本且处于 Wi-Fi 在线状态时，电脑自动发送一个独立更新任务；更新任务不得触发作品去重、移动、归档或自动补货。
- GitHub 可用时手机仍优先使用公开更新索引；GitHub 不可用时，电脑局域网推送应进入同一 APK 校验、用户确认安装和重新上线确认链路。
- 更新失败或手机未点击安装时，电脑应进入冷却期，不重复发送同一 APK；手机重新上报新版本后才视为升级完成。
- Android 每次打开自动检查；发现新版后不打开浏览器，先显示“稍后 / 下载更新”。
- 用户确认后由应用自有 HTTPS 服务显示前台进度通知，支持断点续传；失败时保留进度，校验失败时删除临时包。
- 下载完成后按 SHA-256、包名、版本码和签名校验；合格包改名进入应用私有更新目录，并显示“安装”入口。
- 用户点击安装后进入 Android 系统安装器；首次按系统提示允许“来自此来源”，最终仍由用户确认，应用不得静默安装。
- 解包正式 APK，确认包含 `REQUEST_INSTALL_PACKAGES`、`FOREGROUND_SERVICE_DATA_SYNC`，不含特权 `INSTALL_PACKAGES` 或 `application-debuggable`；CI 必须把越权或 Debug 作为失败条件。
- iPhone 检查更新不打开浏览器；自用侧载版明确提示由电脑重新签名覆盖，不宣称 App 能自行静默安装 IPA。
- 正式发布前用一个比当前安装版本更高的受控更新索引验证完整 Android 流程，完成后恢复正式索引。

### 9. iOS 12 App 内文件夹选择

- “选择作品文件夹”至少列出“全部接收内容”和已接收的普通子目录，忽略隐藏目录、相册回收站及其数字重名副本。
- 分别选择一级和多级聚合目录，确认数字只统计直接含图片与 TXT 的作品目录。
- 删除或移走已保存的子目录后重启 App，应安全回退到“全部接收内容”，不出现空白或崩溃。
- iOS 13+ 仍走系统外部文件夹选择和 bookmark 恢复，不因 iOS 12 兼容入口而改变。

### 10. 设备作品数

- 手机扫描结果分别为 0、1、2、15 时，发现包与 `/v2/info` 返回相同非负整数；作品名称、文案、图片和路径不得出现在状态数据中。
- Windows 卡片和手机互传列表都保留原设备名，并显示“设备名（作品数 X）”。
- 旧版发现包没有第 9 个字段时，三端仍能发现和传送，界面不显示数字且不能误报为 0。
- 手机接收并提交新作品、手动刷新、次日回收或清空后，下一轮广播更新数量。
- 共享技能的 `--status` 与指定 `--device` 查询分别覆盖全部设备、单设备、重名设备和旧版数量未知场景。

- 混合准备精准流量、泛流量和未分类作品，确认 `/v2/info.workCounts` 各分类之和等于 `workCount`；删除或新增任一分类后只改变对应分类与总数。
- 旧版设备缺少 `workCounts` 时，自动分发必须显示分类库存未知，不能把总数代替精准或泛流量数量。

### 11. Android 固定顶部工具栏与单页模式

- 准备超过一屏的作品，向下滚动到底；模式、小飞机、回收站和设置始终固定在顶部，刷新通过下拉手势触发。
- 点击文件夹模式按钮后，当前 Activity 不变，顶栏位置不变，只有下方作品卡片切换成文件列表；再次点击三点连线图标原地返回作品。作品和文件模式均下拉刷新，顶部不重复显示刷新按钮。
- 文件模式进入两级子目录后，第一次返回只退一级；回到根目录后再返回只切回作品，不退出应用。
- 文件夹、图片、文本、PDF、ZIP/7z/RAR、视频、音频和未知文件分别核对图标；ZIP 图标不得与回收站垃圾桶混淆。
- 点击模式、传送、回收站和设置均应出现对应短文字反馈；下拉刷新开始与完成时显示状态和真实数量。
- 下拉不足阈值显示“下拉刷新”并复位；超过阈值依次显示“松开刷新”、旋转图标与“正在刷新…”，完成后显示真实数量再收起，同一次手势只能执行一次刷新。
- 设置页逐个切换胶囊开关：灰色与绿色轨道都必须保持完整椭圆，白色圆点不得超出或融进卡片；点击整行与直接点击开关各只切换一次。
- 开启“自动发送到主设备”但尚未选择目标时应立即弹出设备选择；只显示可信设备，并区分在线、离线和未选择。
- 更新回归使用旧一版实体安装：打开应用应先弹“发现新版本”，拒绝时不下载；确认后显示系统下载进度；完成后只保留系统下载通知，不得出现应用内安装按钮或抢占界面。下载项必须使用英文 `.apk` 文件名，用户点击系统通知后再进入安装流程。
- 在滚动中长按作品，右下角垃圾桶保持可见且不覆盖顶部工具栏；进入回收站或按返回键后选择状态消失。
- 在水滴/刘海或 Android 15+ 边到边设备上，五个顶部入口必须完全位于状态栏安全区下方；横屏时不得进入左右挖孔区。
- 在 320dp/360dp 宽度及系统大字体下检查标题、数字和设置按钮不换行、不互相遮挡；纯图标仍要有可辨认的点击区域与无障碍名称。
