# 三端兼容与测试矩阵

更新时间：2026-07-19

## 不拆包原则

- Android 始终使用 `com.zwm.gallery`、同一签名和同一升级链；不制作红米版、华为版。
- iPhone 始终使用 `com.zwm.album`；同一 IPA 根据系统能力切换目录方式。
- Windows 只有一套原生面板；作品识别不是传输前置条件，任意文件都能传。
- 修复旧设备时必须同时保留新设备路径，自动化用例至少覆盖公共逻辑与系统分支。

## iOS 系统能力边界

- iOS 12 没有“给第三方 App 持久授权任意外部文件夹”的系统能力，因此 iPhone 6 自动使用应用 Documents 目录；该目录通过系统“文件”与 iTunes 文件共享进入。
- iOS 13 及以上可选择外部总文件夹，也可在设置中切回应用 Documents 目录。
- 两条路径共用 `WorkScanner`：最多递归 8 层、1000 个文件夹，同时含图片与 TXT 才是作品。

## 通用传输与作品识别的边界

1. Windows 负责把普通文件直接发送，把电脑文件夹临时整理为保留相对路径的 ZIP。
2. Android 接收层把所有内容写入用户设置的接收目录；iPhone 仅展开 Windows 为文件夹传输生成的存储式 ZIP。两端都拒绝绝对路径和 `..` 越界。
3. 作品扫描层只把“同一目录中至少一张图片 + 一个 TXT”加入作品列表。
4. PDF、视频、表格、文档、源文件等不会被误判成作品，但仍会完整保留。

## 已踩坑与回归要求

- SAF 与 Android 10 隐藏目录通道可能看到同一个作品：必须按真实来源路径去重，不能只比较内部编号。
- 多个 `WorkLibrary` 同时启动会竞争历史迁移：迁移必须进程内串行化，并保留并发回归测试。
- Windows ZIP 可能用反斜杠表示目录项：目录判断同时接受 `/` 与 `\`，否则会生成同名空文件和“(1)”目录。
- macOS CI runner 不一定预装可启动的 iPhone 模拟器：有运行时就执行测试；没有时至少编译 App 与测试包，再执行真机 SDK 构建。
- iPhone 6 不能依赖 SwiftUI 生命周期、NavigationStack、SF Symbols 或 iOS 13 动态系统色；兼容 UI 使用 UIKit 和版本保护。
- 实机测试数据完成后必须清理，并再次核对用户原作品数量，避免测试素材污染作品库。
