# 相册投送中控 V4.1.2 / Android 0.6.9 / iPhone 0.6.7

## Android 0.6.9 确认式更新流程

- 每次打开应用自动检查版本；发现新版先弹出更新提醒，由用户点击“下载更新”。
- 下载完成并通过校验后，应用内弹出包含版本、APK 文件名和大小的安装提醒；用户点击“安装”才进入 Android 系统安装器。
- 如果下载完成时应用不在首页，保留常驻安装通知；下次回到首页再次显示安装提醒。
- 不再尝试自动拉起受系统限制的安装页面，也不会静默安装。

## Android 0.6.8 真机交互修复

- 首页文件夹模式入口移到左侧；四分类滑块修复遮字和宽度偏差，选中文字始终清晰可见。
- 下拉刷新补齐“下拉刷新、松开刷新、正在刷新、完成数量”四段状态和旋转进度，不再只有阻尼位移。
- 设置页使用应用自行绘制的 iOS 式胶囊开关，避免小米、华为等厂商系统控件出现滑块溢出或轨道残缺；标题与浅色小字分层并完整换行。
- “自动发送到主设备”增加真实目标设备选择，明确显示在线、离线或未选择。
- 新版 APK 下载并通过大小、SHA-256、包名、版本和签名检查后，应用仍在前台时自动打开系统安装页；退到后台时保留通知入口。
- Redmi Note 8 已完成同签名覆盖安装与首页、分类、下拉刷新、设置、主设备选择真机检查。

## 0.6.7 下拉刷新收口

- Android 与 iPhone 首页删除重复的顶部刷新按钮，作品和文件列表统一下拉刷新；Android 回收站仍保留必要的返回按钮。

## 0.6.6 双端原生交互统一

- 双端首页删除重复的“作品 + 总数”，数量统一显示在“全部、转化、泛流量、未分类”中；iPhone 新增顶部文件夹浏览入口并把刷新图标改为双箭头。
- Android 对齐 iPhone 的浅灰/白/绿色层级，增加分类滑块动画、内容过渡、边缘阻尼回弹和下拉刷新；设置页同样支持克制回弹。
- iPhone 设置移除旧“工作方式、导入、使用我的 iPhone/相册”入口，补齐前台剪切板同步、截图识别、自动发送、主设备选择和主设备接收；长说明改为标题下方浅色小字。
- iPhone 受系统限制不提供跨应用悬浮球或后台永久读取；回到相册后补读剪切板和新截图。

## 0.6.5 双端分类与自动整理

- iPhone 首页显示全部、转化、泛流量、未分类四个筛选及数量，窄屏使用紧凑标签；筛选后打开作品会严格使用当前筛选结果。
- Android 与 iPhone 的自动整理统一为两条紧凑设置项，点开可选立刻、1/3/6/24 小时或自定义 0～720 小时，选择后即时保存。
- Redmi Note 8 已从正式 0.6.4 同签名覆盖至 0.6.5 候选，原作品、Lark 目录和设备名保留；iPhone 等待重新连接后侧载验收。

## 0.6.4 / 0.5.3 / V4.1.2 局域网剪切板与截图中转

- Android 悬浮剪切板首次显示在状态栏下方、水平居中，宽高各占可用屏幕 50%；支持拖动、缩放、尺寸位置记忆，点外部立即收起但保留悬浮球。
- 悬浮球长按 5 秒可关闭 1 分钟、30 分钟或永久关闭；临时关闭到期自动恢复，永久关闭后在设置重新开启。
- 最新剪切内容置顶、长文本默认折叠；Android 收到可信设备的新剪切后写入系统剪切板，iPhone 仅在应用前台读写，Windows 轮询本机剪切板。三端使用消息 ID、来源和跳数去重，避免多机循环覆盖。
- Android 设置增加“自动识别新截图”“自动发送到主设备”“允许作为主设备接收”。没有自动目标时先保留待确认记录，进入应用后再选择设备。
- Android、iPhone 和 Windows 支持可信局域网/热点设备间中转。中转任务最多保留 1 小时，按消息 ID 去重并限制跳数；下一节点接收后删除本节点临时副本。iPhone 中转受前台和系统短暂后台时间限制，重新进入应用后继续队列。
- Android 更新包使用纯英文 `.apk` 文件名。系统下载完成后先校验 SHA-256、包名、版本、可解析性和签名，再显示安装入口；无效副本自动删除并允许重下，仍不申请“安装其他应用”权限。
- 手机版不接入坚果云或公网云盘；本轮中转只走局域网、热点和设备间直连。
- 自动构建已覆盖 Android 单元测试、正式构建和 Lint；红米 0.6.3 → 0.6.4、华为文件功能以及 iPhone 前台中转仍需连接对应实体设备后逐台验收。

## Windows V4.1.1 单窗口投送工作台

- Windows 中控改为单窗口工作台：左侧是较窄的素材目录、作品列表和归档操作，右侧是主要的在线设备与其他文件传送区域，底部统一显示进度、取消和诊断；不再弹出独立素材库窗口。
- 日常流程压缩为“左边选素材 → 右边选设备 → 传送选中素材”；双击素材也可直接传送，并继续使用现有 USB → WiFi 选路。
- 设置素材目录、设置归档目录、刷新、传送和“已使用并归档”都在主窗口完成。系统目录选择器和危险操作确认仍会按需出现。
- 原有拖放完整保留：任意文件、ZIP 或整个文件夹仍可直接拖到右侧设备卡片。设备备注、作品数和 USB/WiFi/远程开关继续读取原有本机数据。
- 修复设备列表在 15 秒未收到手机广播时被删除、手动刷新又清空已知设备的问题；刷新现在保留设备并主动探测，最近发现的设备保留 10 分钟，避免手机后台广播节流导致列表闪空。
- 成功传送历史升级为 `%LOCALAPPDATA%\ZwmDeviceShareHub\content-history.db`。旧 `transfer-history.tsv` 首次启动只导入一次且原文件保留；数据库不可用时传送会安全退回旧记录方式。
- 数据库保存内容指纹、当前路径、目标设备、通道、时间和归档事件；文件夹仍可在资源管理器里正常移动和改名，内容指纹负责识别同一素材。
- “已使用并归档”先生成 ZIP，检查 ZIP 目录结构和文件数，再比较复制前后的 SHA-256；只有校验成功才把原文件夹移入 Windows 回收站。失败时不永久删除原目录，也不覆盖同名归档包。
- 素材目录和归档目录记在同一数据库中。归档包已生成但原目录无法进入回收站时，数据库保留 `archive_ready` 状态，原文件夹继续留在原位。

## Android 0.6.2 剪切板同步与更新可靠性

- 固定常用语点一次就会复制并成为最新剪切，立即同步当前在线手机；本机只保留最新一条剪切内容，不保存整套同步历史。
- 同一设备离线超过在线窗口后重新出现，会自动补齐当前最新剪切与固定常用语；并发编辑和相同时间戳冲突会在各手机收敛到同一结果。
- 悬浮面板在用户点开后获取焦点并稍候读取系统剪切板，以适配 Android 10+ 的剪切板隐私限制；新增话术前自动收起面板，不遮挡编辑界面。
- 同一版本的更新包正在下载或已经校验完成时不会重复下载；安装完成后清理本软件跟踪的旧 APK，失败或被外部删除后可以重新下载。

## Android 0.5.7 / Windows V3.8 内容去重与 USB 优先

- Windows 会对每个顶层文件或文件夹计算内容指纹。文件使用 SHA-256；文件夹使用“排序后的相对路径 + 文件大小 + 每个文件 SHA-256”，不会只凭作品数或图片数判断。
- 同一内容再次传给同一设备时，会显示上次传送时间和设备，默认跳过；仍可明确选择重新传送。只有手机确认接收完成后才写入本机传送记录。
- Windows 现在同时发现 USB 与 Wi‑Fi。Android 开放“文件传输”后直接写入 `Download/Lark`；iPhone 通过已安装“相册”的文件共享目录接收。两条通道同时可用时自动按 USB → Wi‑Fi 选择。
- Android 修复系统文件管理器已删除作品、App 私有副本仍可预览和分享的问题。缺失项要经过两次确认才移除，防止小米、华为文件服务短暂返回空目录造成误清理。
- 红米 K60 实测中，外部目录 24 个作品、旧库残留 26 个活动项和 2 个回收项；升级扫描后恢复为 24 个活动项、0 个回收项，原外部作品未被改动。

- 按返回键或取消最后一个勾选会退出多选，不会删除作品。

## 0.4.7 分身分享与固定工具栏

- Android 10+ 会像系统图库一样，先把作品图片原样放进系统媒体库的“相册分享缓存”，再打开系统分享面板；这条通道用于改善小米、VIVO 应用分身对应用私有图片地址兼容不稳定的问题。
- 临时分享副本在下一自然日打开相册时清理，不修改作品原图、文案、分享次数或回收站。Android 8/9 自动使用原有普通分享通道。
- Android 顶部工具栏固定在屏幕上；长按一张作品卡片后，右下角出现垃圾桶，可把作品及真实来源文件夹移到现有“相册回收站”。
- 设备名称保持手机或电脑原有命名，只在数量已知时追加括号，例如“红米 K60（作品数 25）”。
- Android 必须用同包名、同签名 APK 覆盖安装；不要卸载或清除应用数据。覆盖安装会保留作品文件夹授权、作品库、分享次数和回收站状态。

## 0.4.6 设备作品数

- 手机仍在本机递归扫描作品；局域网只公布当前扫描数量，不传作品名、图片、文案或目录。
- Windows 设备卡片直接显示“在线 · 15”一类数字；Android 与 iPhone 的互传设备列表也显示对方作品数。
- 可直接让共享 AI 查询：“现在每台手机有多少作品？”或“iPhone6 有多少作品？”。

- Android 0.6.3、iPhone 0.5.2 和 Windows V4.1.1 为当前交付版本；Android 默认在每次打开时检查并交给系统下载新 APK，下载文件固定保留 `.apk` 后缀，也可在设置中关闭，iPhone 仍通过电脑侧载覆盖。

## 0.4.5 更新体验与 iPhone 6 文件夹

- Android 0.5.3 起，设置里点击更新后交给系统下载并显示系统进度通知；完成后点通知安装。相册不再申请安装其他应用权限，下载后仍核对 SHA-256，也不跳转浏览器。

- 苹果官方“文件”App 与“相册”是两个独立 App。iPhone 6 即使没有安装“文件”，同 Wi-Fi 接收、App 内文件夹选择和作品扫描仍可工作；安装官方“文件”后只是多一个手动导入入口。
- 手机接收重名目录时可能自动生成“相册回收站 (1)”一类副本；0.4.5 会把这些目录继续视为回收站，不再把其中旧作品重复显示到首页。

V3.8 把电脑、Android 和 iPhone 统一成可互相发现、互相传送并查看作品数量的设备。三端均可接收普通文件和文件夹；电脑继续支持直接拖放，并优先使用已开放的 USB 文件传输。两端应用都叫“相册”，不需要填写 IP、配对码，也不依赖 ADB、Root、无障碍或设备管理权限。

## 最短使用流程

1. 手机打开“相册”，电脑打开原生 Windows 面板。
2. 把任意文件、ZIP 或整个文件夹拖到手机卡片；文件夹由电脑自动整理，不需要手动压缩。
3. 文件会原样放进手机设置的接收文件夹；ZIP 和电脑文件夹保留内部目录结构。含“图片 + TXT”的子文件夹会额外显示为作品。
4. 点作品的“复制文案并分享”。
5. App 复制 TXT 文案、带上全部图片并打开 Android 系统分享面板。

手机互传：在任一手机主界面点顶部纸飞机，点接收设备，再点“选择文件”或“选择文件夹”。电脑接收内容默认保存在 `下载/相册收件箱`。iPhone 作为接收端时需要让“相册”保持在前台；应用会阻止自动锁屏，离开应用后立即恢复系统锁屏规则并停止接收。

AI 直接传送：共享环境已提供 `device-folder-transfer` 技能。可直接说“把某某文件夹发到某某设备”，技能会按名称发现唯一设备、核对源目录、显示进度、失败回滚并验证结果，不要求填写 IP 或配对码。旧 iPhone 连接 USB 且大目录较大时会自动使用更稳定的文件共享路径。

AI 查询数量：可直接说“查一下所有手机有多少作品”或“查某台手机的作品数”。结果来自手机最近一次实际扫描；手机接收新文件、打开 App 或手动刷新后会同步更新。

Android 无法知道用户是否在目标平台完成发布，因此状态显示为“已发起分享”，代表用户点过入口，不宣称目标平台发布成功。

## ZIP 作品规则

- 递归寻找子文件夹。
- 一个子文件夹的直接内容同时包含至少一张支持的图片和一个 `.txt`，才判定为作品。
- 图片支持 JPG、JPEG、PNG、WEBP、HEIC、HEIF。
- 文案优先使用 `文案.txt`；否则按自然顺序使用第一个 TXT。
- 图片按自然顺序排列，例如 `2.jpg` 在 `10.jpg` 前面。
- 多个 TXT 会显示提示。
- 拒绝 ZIP 路径越界，并限制作品数、单作品图片数和文件大小。

## 手机文件夹

第一次点“选择 Lark 文件夹”，使用 Android 系统文件夹选择器授权一个目录。App 保存该授权，以后点“刷新”即可递归读取。Android 11 以后通常不允许第三方应用直接授权整个 Download 根目录，因此优先选择 `Download/Lark` 或实际保存作品的子文件夹。

读取规则与 ZIP 相同。文件会导入 App 私有作品库，避免目标平台在分享过程中失去读取权限。电脑传入的任意文件会写入该目录；ZIP 和电脑文件夹会按原目录结构展开。只有符合“图片 + TXT”的目录才进入作品列表，普通文件仍作为通用传输文件保留。

## 作品状态和回收站

- 每次点击“复制并分享”后立即显示“已发起分享 N 次”；系统分享面板取消、厂商回调缺失或目标启动较慢都不会把这次点击漏掉。
- 再次分享会先显示已有次数，确认后才继续，兼顾多平台发布与防止误发。
- 默认从第一次点击起 1 小时后移入回收站，并在同一小时边界从文件管理中彻底删除；两个时间可在设置中分别调整为 1～10 小时。
- 升级前只有日期的旧记录按北京时间迁移：昨天及更早内容视为已到期；当天内容从升级时起保留完整 1 小时，避免误删。
- Android 可长按作品卡片，再点右下角垃圾桶立即移入回收站；移动成功后原位置不再显示，分享次数仍保留。

## Windows 面板

- 主界面是纯 Win32 C++，不依赖浏览器、Node.js 或 .NET。Android USB 使用 Windows 自带便携设备接口；iPhone USB 文件共享由随 EXE 内置的桥接脚本调用本机既有 Apple 驱动与 Python 组件。
- EXE、任务栏和桌面快捷方式使用与手机版一致的绿色“相册投送”图标。
- 自动发现同一 Wi‑Fi 的手机。
- 右上角“刷新设备”会立即清空旧列表并重新探测；断网或离线设备不会继续假在线。
- 支持直接拖任意文件、多个文件、ZIP、单个作品文件夹或复杂聚合文件夹；嵌套目录会保留，不要求它必须是作品。
- 直接拖图片时，手机前台自动打开系统分享；手机在后台时点接收通知即可进入分享。
- 单文件上限 4GB；这是当前 WinHTTP 与 ZIP32 实现的明确边界。
- 单次最多 100 个顶层拖入项目；单个文件夹内部最多 10000 个文件，解压总量上限 20GB。
- 拖放后显示真实进度条、百分比、已传大小、总大小和速度。
- 支持取消正在进行的传送。
- 显示清晰错误，并可打开诊断日志。
- 电脑同时是接收设备；手机可自动发现电脑并把文件或文件夹传到 `下载/相册收件箱`。
- 右下角“传送”按钮可先选设备，再选择文件或文件夹；原有拖放操作保持不变。

## 设置与图片信息

- 设置页保留手机名称、作品文件夹、提醒开关、当前版本、检查更新和软件说明。手机名称会显示在电脑端。
- “声音通知”和“震动提醒”可以分别开关，默认都关闭。只有主动打开声音通知时才申请系统通知权限；安卓为维持局域网接收而显示的常驻服务提示始终静音且不震动。
- App 每天静默检查一次 GitHub Release；也可在设置中手动检查。Android 在 App 内下载并校验 APK 后交给系统安装器；iPhone 自用侧载版由电脑重新签名覆盖。
- 传输和分享保持图片原始字节，因此已有 EXIF 拍摄时间、相机参数和位置会原样保留。
- 不注入虚假的相机、地址或拍摄参数，也不提供伪造元数据开关。
