# 相册投送中控 V3.7

## 0.5.0 作品内容预览与三图标操作

- 点作品白色卡片进入内容预览：文案在前，图片按 3:4 比例一行两张；点图片看大图，长按图片进入多选。
- 多选后底部只保留三个图标：垃圾桶移入图片回收站、三点连线分享到其他应用、小飞机传送到其他设备。图片回收站保留 7 天，可在作品内恢复。
- 首页原“复制并分享”按钮继续保持原动作，不改变熟悉的快速流程。
- Android 0.5.0、iPhone 0.5.0 与 Windows V3.7 使用同一套绿色相册图标和视觉语言；Windows 设备名前区分 Android / iPhone。
- VIVO 分身冷启动会等待系统真正打开目标应用；若目标未打开，不会误加分享次数。iPhone 6 预览采用低内存缩略图。

## Android 0.4.9 旧机型联网恢复

- 修复旧版 Android / MIUI 在 Wi‑Fi 短暂断开或切换后，接收服务仍在线但设备发现永久停止的问题。
- 发现通道遇到临时网络错误会自动重建，不再要求退出或重开相册；恢复过程会写入诊断并给出清晰状态提示。
- 保持同一个 `com.zwm.gallery` 包和原签名覆盖升级，目录授权、作品、分享次数和回收站均继续保留。

## Android 0.4.8 批量回收

- 长按任意作品进入多选，卡片右上角出现复选框；继续点卡片或复选框即可勾选多个。
- 顶部显示“已选 N 个”，右下角垃圾桶一次把选中作品移入现有“相册回收站”；分享次数继续保留。
- 按返回键或取消最后一个勾选会退出多选，不会删除作品。

## 0.4.7 分身分享与固定工具栏

- Android 10+ 会像系统图库一样，先把作品图片原样放进系统媒体库的“相册分享缓存”，再打开系统分享面板；这条通道用于改善小米、VIVO 应用分身对应用私有图片地址兼容不稳定的问题。
- 临时分享副本在下一自然日打开相册时清理，不修改作品原图、文案、分享次数或回收站。Android 8/9 自动使用原有普通分享通道。
- Android 顶部工具栏固定在屏幕上；长按一张作品卡片后，右下角出现垃圾桶，可把作品及真实来源文件夹移到现有“相册回收站”。
- 设备名称保持手机或电脑原有命名，只在数量已知时追加括号，例如“红米 K60（作品数 25）”。
- Android 必须用同包名、同签名 APK 覆盖安装；不要卸载或清除应用数据。覆盖安装会保留作品文件夹授权、作品库、分享次数和回收站状态。

## 0.4.6 设备作品数

- 手机仍在本机递归扫描作品；局域网只公布当前扫描数量，不传作品名、图片、文案或目录。
- Windows 设备卡片直接显示“在线 · 15”一类数字；Android 与 iPhone 的互传设备列表也显示对方作品数。
- 可直接让共享 AI 查询：“现在每台手机有多少作品？”或“iPhone6 有多少作品？”。
- 旧版手机没有作品数字字段时仍可发现和传送，界面不会用 0 冒充未知数量。
- Android 0.5.0、iPhone 0.5.0 和 Windows V3.7 为当前交付版本；Android 设置里的“检查更新”会直接下载并校验新 APK，iPhone 仍通过电脑侧载覆盖。

## 0.4.5 更新体验与 iPhone 6 文件夹

- Android 在设置里点击更新后，直接在 App 内下载 APK，显示百分比、已下载大小和总大小，并在下载后校验 SHA-256；不再跳转浏览器。Android 最后的系统安装确认属于系统安全边界，仍需用户确认。
- iPhone 检查更新不再跳网页。自用侧载版必须由电脑重新签名覆盖，iOS 不允许 App 自己替换 IPA。
- iPhone 6 / iOS 12 的设置页现在也叫“选择作品文件夹”。它会列出“相册”自己的接收目录及其子文件夹，可任选一个作为递归扫描根目录；iPhone 12 等 iOS 13+ 设备继续使用系统外部文件夹选择器。
- 苹果官方“文件”App 与“相册”是两个独立 App。iPhone 6 即使没有安装“文件”，同 Wi-Fi 接收、App 内文件夹选择和作品扫描仍可工作；安装官方“文件”后只是多一个手动导入入口。
- 手机接收重名目录时可能自动生成“相册回收站 (1)”一类副本；0.4.5 会把这些目录继续视为回收站，不再把其中旧作品重复显示到首页。

V3.7 把电脑、Android 和 iPhone 统一成同一 Wi‑Fi 下可互相发现、互相传送并查看作品数量的设备。三端均可接收普通文件和文件夹；电脑继续支持直接拖放。两端应用都叫“相册”，不需要填写 IP、配对码，也不需要 Node.js、命令行、ADB、Root、无障碍或设备管理权限。

维护者或其他 AI 请先读 [AGENTS.md](AGENTS.md) 和 [维护交接](docs/MAINTAINER_HANDOFF.md)。历史 Bug 与回归要求见 [Bug 账本](docs/BUG_LEDGER.md)，三端检查步骤见 [测试手册](docs/TEST_PLAYBOOK.md)。

## 最短使用流程

1. 手机打开“相册”，电脑打开原生 Windows 面板。
2. 把任意文件、ZIP 或整个文件夹拖到手机卡片；文件夹由电脑自动整理，不需要手动压缩。
3. 文件会原样放进手机设置的接收文件夹；ZIP 和电脑文件夹保留内部目录结构。含“图片 + TXT”的子文件夹会额外显示为作品。
4. 点作品的“复制文案并分享”。
5. App 复制 TXT 文案、带上全部图片并打开 Android 系统分享面板。

手机互传：在任一手机主界面点顶部纸飞机，点接收设备，再点“选择文件”或“选择文件夹”。电脑接收内容默认保存在 `下载/相册收件箱`。iPhone 作为接收端时需要让“相册”保持在前台；应用会阻止自动锁屏，离开应用后立即恢复系统锁屏规则并停止接收。

AI 直接传送：共享环境已提供 `device-folder-transfer` 技能。可直接说“把某某文件夹发到某某设备”，技能会按名称发现唯一设备、核对源目录、显示进度、失败回滚并验证结果，不要求填写 IP 或配对码。旧 iPhone 连接 USB 且大目录较大时会自动使用更稳定的文件共享路径。

AI 查询数量：可直接说“查一下所有手机有多少作品”或“查某台手机的作品数”。结果来自手机最近一次实际扫描；手机接收新文件、打开 App 或手动刷新后会同步更新。

Android 无法知道用户是否在目标平台完成发布，因此状态诚实显示为“已打开分享”，不宣称“发布成功”。

## ZIP 作品规则

- 递归寻找子文件夹。
- 一个子文件夹的直接内容同时包含至少一张支持的图片和一个 `.txt`，才判定为作品。
- 图片支持 JPG、JPEG、PNG、WEBP、HEIC、HEIF。
- 文案优先使用 `文案.txt`；否则按自然顺序使用第一个 TXT。
- 图片按自然顺序排列，例如 `2.jpg` 在 `10.jpg` 前面。
- 多个 TXT 会显示提示。
- 拒绝 ZIP 路径越界，并限制作品数、单作品图片数和文件大小。

## 手机文件夹

第一次点“选择 Lark 文件夹”，使用 Android 系统文件夹选择器授权一个目录。App 保存该授权，以后点“刷新”即可递归读取。Android 11 以后通常不允许第三方应用直接授权整个 Download 根目录，因此优先选择 `Download/Lark` 或实际保存作品的子文件夹。

读取规则与 ZIP 相同。文件会导入 App 私有作品库，避免目标平台在分享过程中失去读取权限。电脑传入的任意文件会写入该目录；ZIP 和电脑文件夹会按原目录结构展开。只有符合“图片 + TXT”的目录才进入作品列表，普通文件仍作为通用传输文件保留。

## 作品状态和回收站

- 每次打开系统分享目标后，作品显示“已打开分享 N 次”。旧版本已有的分享记录从升级后的首次再次分享开始计数。
- 当天保留在作品列表。
- 下一自然日自动进入回收站。
- 回收站可恢复，进入 7 天后自动清理。
- Android 可长按作品卡片，再点右下角垃圾桶立即移入回收站；移动成功后原位置不再显示，分享次数仍保留。

## Windows 面板

- 纯 Win32 C++，不依赖浏览器、Node.js、Python 或 .NET。
- EXE、任务栏和桌面快捷方式使用与手机版一致的绿色“相册投送”图标。
- 自动发现同一 Wi‑Fi 的手机。
- 右上角“刷新设备”会立即清空旧列表并重新探测；断网或离线设备不会继续假在线。
- 支持直接拖任意文件、多个文件、ZIP、单个作品文件夹或复杂聚合文件夹；嵌套目录会保留，不要求它必须是作品。
- 直接拖图片时，手机前台自动打开系统分享；手机在后台时点接收通知即可进入分享。
- 单文件上限 4GB；这是当前 WinHTTP 与 ZIP32 实现的明确边界。
- 单次最多 100 个顶层拖入项目；单个文件夹内部最多 10000 个文件，解压总量上限 20GB。
- 拖放后显示真实进度条、百分比、已传大小、总大小和速度。
- 支持取消正在进行的传送。
- 显示清晰错误，并可打开诊断日志。
- 电脑同时是接收设备；手机可自动发现电脑并把文件或文件夹传到 `下载/相册收件箱`。
- 右下角“传送”按钮可先选设备，再选择文件或文件夹；原有拖放操作保持不变。

## 设置与图片信息

- 设置页保留手机名称、作品文件夹、提醒开关、当前版本、检查更新和软件说明。手机名称会显示在电脑端。
- “声音通知”和“震动提醒”可以分别开关，默认都关闭。只有主动打开声音通知时才申请系统通知权限；安卓为维持局域网接收而显示的常驻服务提示始终静音且不震动。
- App 每天静默检查一次 GitHub Release；也可在设置中手动检查。Android 在 App 内下载并校验 APK 后交给系统安装器；iPhone 自用侧载版由电脑重新签名覆盖。
- 传输和分享保持图片原始字节，因此已有 EXIF 拍摄时间、相机参数和位置会原样保留。
- 不注入虚假的相机、地址或拍摄参数，也不提供伪造元数据开关。
