# 团建文案三版生成 Skill｜公开版

## 1. 默认输出

用户直接粘贴一段团建 / 周边游 / 企业活动素材，或说“出文案”时，默认直接输出 3 个版本：

1. **小红书1｜自然攻略版**
2. **小红书2｜高密度种草版**
3. **抖音｜攻略版**

如果用户明确只要某一版，则只输出指定版本。

---

## 2. 共同事实门

先在内部建立事实账本，再写成稿。

可以直接使用：
- 用户明确提供的地点
- 已明确的项目 / 景点 / 餐饮 / 住宿
- 已明确的人数、价格、车程、开放时间
- 用户明确确认的长期业务能力

禁止自行编造：
- 价格 / 人均
- 固定人数容量
- 固定车程
- 固定车型 / 座位数
- 营业时间
- 房型 / 库存
- 客户案例 / 评价
- “已含”“免费”“不限量”等承诺
- 未提供的具体活动项目

发布稿不要出现生产过程旁白，例如：
“原文里”“根据素材”“图片显示”“素材没有提供”“本图集”“整理时发现”。

已确认的信息直接自然写；没确认的信息直接删掉，不向读者汇报“缺什么”。

---

## 3. 小红书1｜自然攻略版

目标：
- 像成熟运营本人写的自然攻略
- 有信息，但不过度堆栏目
- 不像方案书，不像 AI 摘要
- 可以正常保留团建 / HR / 行政 / 公司团建等业务语义

推荐结构：
- 一个有画面或选择价值的标题
- 直接进入场景 / 判断
- 基础信息（有事实才写）
- 玩法 / 路线 / 项目展开
- 不同团队怎么选
- 1 组集中提醒
- SEO 标签

避免：
- “方案名称 / 适用对象 / 核心模块 / 综合评估 / 价值赋能”
- 每篇都写“别排太满 / 慢下来 / 更舒服”
- 每篇都套同一组小标题

标题要有具体钩子，优先用：
- 真实项目组合
- 反差
- 选择冲突
- 具体场景
- 明确收益

---

## 4. 小红书2｜高密度种草版

详细模板见：
`references/high-density-template.md`

核心感觉：
- 标题能搜
- 第一屏有情绪
- 参数卡清楚
- 项目亮点密集
- 参考时间轴完整
- 玩法池丰富
- Emoji 有层级
- SEO 话题完整

### 允许主动排“参考时间轴”

当用户已经明确是一日 / 半日 / 2天1夜等时长时，可以根据真实项目，自主排出合理的参考时间，例如：

```text
09:30｜抵达
10:00｜项目A
12:00｜午餐
14:00｜项目B
16:30｜自由活动
18:00｜烧烤
```

必须标明：
- “1日行程参考”
- “2天1夜行程参考”
- 或“参考时间轴”

这些时间是策划参考，不代表景区官方营业时间、固定班次或供应商硬承诺。

### 长度

素材充足时：
- 目标 **900—980 字符**
- **1000 字符以内即可**
- 超过 1000 再压缩
- 不需要为了保险压到 700 多字

压缩顺序：
1. 删重复解释
2. 缩短同义判断
3. 合并提醒
4. 精简重复标签

优先保留：
- 地点 / 项目名
- 参数卡
- 核心时间轴
- 玩法池
- 搜索关键词

---

## 5. 抖音｜攻略版

抖音单独执行更保守的平台表达。

### 单目的地

优先改写成：
- 周末玩法
- 户外体验
- 目的地怎么逛
- 场景 / 项目 / 避坑
- 普通用户阅读视角

默认弱化或删除：
- HR / 行政
- 报价
- 人数承接
- 套餐
- 私信 / 咨询 / 预约 / 下单
- 一站式承接
- 强服务承诺

不要把小红书简单删短；要重新组织语言。

### 多目的地 / 多场地合集

可以根据内容需要保留“团建”搜索词，但仍避免：
- 价格承接
- 私信获客
- 预约下单
- 固定套餐承诺

---

## 6. 排版

三版都使用 U+2800 盲文空格作为手机复制空行。

标准：

```text
标题
⠀
第一段
⠀
第二段
⠀
#标签
```

不要使用：
- 裸空行
- `<br>`
- `&nbsp;`
- 单独一行的“•”来制造空白

高密度版也统一只使用一行 `⠀` 做段落分隔。

---

## 7. 标题规则

标题不是文件名，要有点击理由。

内部先找 3—5 个真实强钩子：
- 项目 / 食物 / 场景
- 反差
- 选择难题
- 数字
- 可感知结果

低优先级壳子：
- XX怎么玩
- XX怎么搭
- XX怎么选
- XX这样安排
- N个方向

不是绝对禁用，但没有具体项目 / 场景支撑时不要用。

高密度版优先：
`地点团建｜项目A+项目B+项目C🍂`

---

## 8. 大合集

当输入包含很多城市 / 场地 / 目的地时：

不要：
- 给每个地点写成长段
- 把多个独立地点硬拼成一条路线

优先：
- 每个地点 1—2 行
- 保留代表项目
- 加一句差异判断
- 最后做“按团队感觉直接选”

例如：
```text
想轻松逛逛｜A / B / C
想进山户外｜D / E / F
想看海｜G / H
```

高密度合集仍要控制在 1000 字符以内。

---

## 9. 季节 / 天气 / 户外项目

采摘、涉水、骑马、越野、明火、篝火、露营等会受季节、天气和场地条件影响。

不要每一项都重复“以实际为准”。

统一在末尾用 1—3 句集中提醒即可。

---

## 10. 交付

默认输出三个独立 `text` 代码块：

- 小红书1｜自然攻略版
- 小红书2｜高密度种草版
- 抖音｜攻略版

除非用户要求解释，否则不要额外输出长篇分析。
