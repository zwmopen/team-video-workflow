# 团建双平台文案 Skill｜公开版

## 0. 默认交付

用户给出团建、周边游、农庄、营地、年会、户外活动、目的地或路线素材，且未指定版本数量时，固定输出：

1. **小红书1｜自然攻略版**
2. **小红书2｜高密度种草版**
3. **抖音｜攻略版**

若用户明确只要某一版，则只输出该版。

默认使用可复制的 `text` 代码块。

段落之间统一使用一行 U+2800：

`⠀`

不要同时再加独立圆点 `•` 当空行分隔，避免手机端空隙过大。

---

## 1. 先做事实账本

写之前先在内部确认：
- 地点
- 季节
- 时长
- 已知项目/玩法
- 路线与先后顺序
- 用户明确给出的时刻
- 餐饮/住宿
- 人数
- 交通/接送
- 价格
- 场地能力
- 天气/季节变量

### 不能凭空编造
不得自行创造：
- 价格、人均价
- 固定车程
- 景区营业时间
- 固定车型/座位数
- 客户案例和好评
- 房型/容量
- “全部包含”“免费接送”等固定履约承诺

缺失信息通常直接不写，不在发布稿里解释“素材没提供”。

---

# 2. 小红书1｜自然攻略版

目标：像成熟运营本人写的自然攻略，而不是 AI 方案书。

特点：
- 开头直接进入场景、选择问题或具体玩法
- 保留团建、HR、行政、公司团队等搜索/业务语义
- 信息丰富，但不过度堆模块
- 项目不只列名词，要说明“为什么值得 / 适合什么团队 / 怎么搭”
- 不虚构亲历，不写“我们刚带完”
- 标题优先具体项目、画面、反差、选择价值

不要机械重复：
- XX怎么玩
- XX怎么搭
- XX怎么选
- 别排满
- 先选方向
- 慢下来

这些不是禁词，但不能每篇都靠它们做标题或核心观点。

---

# 3. 小红书2｜高密度种草版

目标：**丰富、好搜、好看、好收藏、有运营感。**

这是“高密度种草 + 方案信息 + 参考时间轴 + 玩法池 + SEO”的复合模板。

## 推荐结构

```text
{强搜索标题：地点团建｜玩法A+玩法B+玩法C}

{3—5行情绪/季节开场}
⠀
📍 | 地点
⏰ | 时长
🙋‍♀️｜人数（有依据才写）
🚌 | 接送/交通（有依据或用户配置支持才写）
🎯 | 3—4个核心体验
⠀
⭐行程亮点速览
⠀
{玩法A}：画面 + 体验 + 判断
⠀
{玩法B}：画面 + 体验 + 判断
⠀
{玩法C}：画面 + 体验 + 判断
⠀
🗓️ 1日 / 2天1夜行程参考
⠀
09:30｜……
10:30｜……
12:00｜……
……
⠀
🍁【可选玩法池】
玩法A｜玩法B｜玩法C｜……
⠀
✅偏轻松：……
✅偏互动：……
✅偏户外：……
⠀
{1—3句统一提醒}
⠀
#地域词 #目的地词 #核心玩法词 #季节词 #团建词
```

## 高密度版时间轴授权

如果用户明确了“一日 / 半日 / 2天1夜”等总时长，但没有逐项时刻，可以由模型**合理规划参考时间轴**。

必须写成：
- `1日行程参考`
- `2天1夜行程参考`
- `参考时间轴`

这些时间是策划参考，不得冒充景区官方开放时间、固定班次或真实车程。

## 丰富度

素材充足时优先做到：
- 4—6 个亮点
- 一日 6—9 个参考节点
- 9—15 个真实可选玩法
- 2—3 组选择组合
- 8—10 个搜索话题

路线做减法，展示做加法：
- 主路线只排合理数量的项目
- 玩法池继续展示其他真实可选项目

## 长度

高密度种草版：
- 素材充足时目标 **900—980 发布字符**
- **1000 字符以内即可**
- 超过 1000 再压缩
- 素材少时不要为了凑 900 编事实

统计应考虑标题、正文、标点、Emoji、U+2800 和标签。

# 4. 抖音｜攻略版

抖音与小红书**分开处理**。

本 Skill 采用偏保守的运营策略：

### 单目的地
重新写成普通用户的玩法/周末/生活内容，主动降低强商业履约感。

通常不主动写：
- HR/行政
- 报价/价格承接
- 多少人起接
- 私信/咨询/预约/下单
- 大巴接送
- 一站式
- 可定制
- 强“方案承接”表达

`2天1夜`、`第一天/第二天`、景点名、项目名本身不是必须删除；重点是不把“目的地 + 线路 + 方案 + 承接 + 转化”全部堆在一起。

### 多目的地合集
可以按内容需要保留适度团建 SEO，但仍不要写报价、私信、预约和强获客 CTA。

抖音建议最多 5 个标签。

---

# 5. 标题

内部先找 3—5 个真实强钩子：
- 具体项目/食物/场景
- 反差
- 选择冲突
- 明确收益
- 数字信息

再生成多个候选，最终避免三版同构。

高密度版优先：
`地点团建｜玩法A+玩法B+玩法C`

自然攻略版可以更像真实用户/运营的判断和分享。

抖音优先口语化、生活化、画面化。

不依赖：
- 天花板
- 杀疯了
- 闭眼冲
- 老板夸爆

来制造点击。

---

# 6. 小红书与抖音的核心区别

**小红书：事实底线不降，表达丰富度拉高。**

小红书不需要照搬抖音的“去商业词”逻辑，可以在事实/业务能力成立时正常使用：
- 团建
- HR / 行政
- 团建方案
- 一日团建 / 2天1夜
- 路线参考
- 可灵活调整
- 项目丰富
- 大巴接送可安排
- 10人起等业务信息

但以上业务能力必须来自用户配置或明确事实，公开版不替任何使用者默认承诺。

**抖音：单独做更保守的发布表达处理。**

---

# 7. 风险提醒

天气、采摘、涉水、明火、骑马、越野、高空等项目的提醒尽量集中在结尾 1—3 句。

不要每个项目后都写一次“以实际为准”，否则会破坏阅读体验。

推荐自然表达：
- 采摘内容按当季成熟情况安排。
- 水上和户外项目出发前看一下天气与当天开放情况。
- 篝火/明火活动提前确认场地规定。

---

# 8. 发布稿必须隐藏生产过程

最终文案不要出现：
- 原文
- 原稿
- 原素材
- 素材里写
- 图片显示
- 根据资料
- 原文没有提供
- 本文整理
- 整理时发现

有证据的事实直接写；没有的删掉。

---

# 9. 公开版业务配置

公开 Skill 不默认替使用者承诺商业能力。

如果你的业务确实支持，可以在自己的项目配置里声明，例如：

```text
业务能力：
- 10人起接
- 大巴/包车可按预算安排
- 项目组合可灵活调整
```

之后小红书可以自然使用这些信息；抖音仍按抖音规则处理。
