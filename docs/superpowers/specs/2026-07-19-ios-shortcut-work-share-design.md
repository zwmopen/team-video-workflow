# iPhone“作品分享”快捷指令设计

日期：2026-07-19  
项目：`tools/device-share-hub`  
状态：设计已确认，尚未实现、尚未在实体 iPhone 验收

## 1. 目标

在不开发原生 iOS App、不依赖 Mac、Xcode、TestFlight 或后台服务的前提下，用苹果“快捷指令”缩短 iPhone 上的作品发布准备流程。

用户自行把 ZIP 传到 iPhone 并解压到固定的作品总文件夹。快捷指令只负责：

1. 列出有效作品；
2. 显示分享次数；
3. 点选一条作品；
4. 复制 TXT 文案；
5. 收集全部图片并打开 iOS 系统分享面板；
6. 次日将已分享作品移入回收站；
7. 回收站保留 7 天后清理。

不自动选择社交平台、不自动粘贴、不自动点击发布，也不伪装系统相册来源。

## 2. 最短用户流程

首次设置：

```text
添加“作品分享”快捷指令
→ 选择一次固定作品总文件夹
→ 允许读取、移动、保存和删除该目录中的文件
```

日常使用：

```text
手动传入并解压 ZIP
→ 点“作品分享”
→ 点一个作品
→ 提示“文案已复制 · 第 N 次打开分享”
→ iOS 系统分享面板
→ 用户选择平台、粘贴文案并发布
```

日常核心操作保持为“点快捷指令 → 点作品 → 点平台”。

## 3. 目录结构

固定总文件夹由用户首次设置，例如：

```text
作品总文件夹/
├─ 作品一/
│  ├─ 文案.txt
│  ├─ 01.jpg
│  └─ 02.jpg
├─ 作品二/
│  ├─ 文案_20260719.txt
│  └─ 01.png
├─ _相册回收站/
└─ _相册状态.json
```

约束：

- 只检查作品总文件夹的直接子文件夹；不递归把复杂聚合目录整体判为作品；
- 子文件夹直接内容至少包含一张支持图片和一个 `.txt` 才是作品；
- 支持 JPG、JPEG、PNG、WEBP、HEIC、HEIF；
- 优先使用 `文案.txt`，否则按文件名排序使用第一个 TXT；
- 图片按文件名排序后分享；
- ZIP 不由快捷指令读取或解压；
- `_相册回收站` 和 `_相册状态.json` 是系统保留名称，不参与作品识别；
- 点开头的隐藏目录在 iOS Files/快捷指令中的可见性不保证，第一版要求作品文件夹名称不要以点开头。

## 4. 状态模型

所有状态集中保存在总文件夹根目录的 `_相册状态.json`，不修改作品文件夹名称，也不向作品中新增 TXT。

```json
{
  "schemaVersion": 1,
  "works": {
    "作品一": {
      "shareCount": 2,
      "lastShareDate": "2026-07-19",
      "trashedDate": null
    }
  }
}
```

第一版要求总文件夹直接子目录名称唯一，文件夹名称作为状态键。用户重命名作品文件夹后会被视为新作品；旧状态作为孤立记录保留，整理时安全忽略，不据此删除未知文件夹。

状态写入失败时不得打开分享面板，避免用户已经分享但计数没有记录。状态文件损坏时：

1. 不移动、不删除任何作品；
2. 把损坏文件改名为带时间戳的备份；
3. 新建空状态；
4. 显示“分享记录已重建，作品文件没有删除”。

## 5. 分享计数

作品列表动态显示：

- `未分享｜作品名称`
- `已打开分享 1 次｜作品名称`
- `已打开分享 3 次｜作品名称`

用户选中作品后，快捷指令按以下顺序执行：

1. 校验 TXT 和图片仍可读取；
2. 读取并复制文案；
3. `shareCount + 1`，把 `lastShareDate` 写为本机当前自然日；
4. 保存状态成功；
5. 显示复制成功提示；
6. 把全部图片交给系统“分享”动作。

计数含义固定为“已打开分享”，不宣称发布成功。即使用户在系统分享面板取消，本次仍计数，因为快捷指令和 iOS 都无法可靠获知目标平台是否真正发布。

同一天可多次分享，次数持续增加；最后分享日期保持当天。

## 6. 次日回收与 7 天清理

不创建定时自动化，不在后台运行。每次用户启动“作品分享”时，先执行一次维护：

1. 读取本机当前自然日；
2. 对活动作品检查 `lastShareDate`；
3. `lastShareDate` 早于今天的作品，移动到 `_相册回收站`；
4. 移动成功后写入 `trashedDate = 今天`；
5. 回收站内作品到达 `trashedDate + 7 天` 时清理；
6. 清理结束后再显示可分享作品列表。

例子：7 月 19 日分享，7 月 20 日首次运行时进入回收站；7 月 27 日首次运行时从快捷指令回收站清理。

如果用户没有运行快捷指令，维护不会发生。设备关机、快捷指令被删除或文件权限失效时，也不会后台删除文件。

移动或删除失败时保留原文件，显示清晰提示，不继续修改对应状态。

## 7. 恢复机制

作品选择列表末尾提供：

```text
♻️ 查看回收站（N）
```

进入后可以选择一条作品恢复。恢复逻辑：

1. 目标名称在活动目录不存在时，移回总文件夹；
2. 清空 `lastShareDate` 和 `trashedDate`；
3. 保留历史 `shareCount`；
4. 若活动目录已有同名文件夹，停止恢复并提示用户先重命名，禁止覆盖。

用户也可以在 Files 中手工查看 `_相册回收站`，但推荐通过快捷指令恢复，以保持状态一致。

## 8. 权限、隐私和数据位置

- 作品、状态和回收站都保存在用户选择的 Files 文件夹中；
- 不上传文案、图片、文件名或状态；
- 剪贴板只保存当前作品文案；
- 第一次运行时由 iOS 请求文件访问、剪贴板和分享权限；
- 权限被撤销时只提示重新选择，不尝试绕过系统限制；
- 不使用管理员权限、设备管理、越狱、ADB 或自动点击。

## 9. 安装与交付方式

最快的首版方式是在实体 iPhone 的“快捷指令”App 中按交付说明创建一次。完成并验收后，由该 iPhone 通过 iCloud 链接或已验证的快捷指令文件分享；Apple 会对共享副本做验证。

当前 Windows 开发机不能使用 macOS 的 `shortcuts sign` 命令生成可供任何人导入的签名文件。因此在没有 Mac 和已有 iCloud 快捷指令链接时，不承诺直接从 Windows 产出可点击安装的 `.shortcut`。

交付物计划：

- 本设计文档；
- iPhone 逐步搭建说明；
- 动作清单和变量表；
- 实体 iPhone 验收记录；
- 验收后由 iPhone 导出的 iCloud 安装链接或快捷指令文件。

## 10. 错误提示

- 总文件夹不存在：`作品文件夹不可用，请重新选择。`
- 无有效作品：`没有找到“图片 + TXT”的作品文件夹。`
- TXT 为空：`文案是空的，请先检查 TXT。`
- 图片不可读：`有图片尚未下载到本机，请在“文件”中打开后重试。`
- 状态保存失败：`分享记录保存失败，本次没有打开分享。`
- 回收移动失败：`作品未移动，原文件仍保留。`
- 删除失败：`清理失败，作品仍在回收站。`
- 同名恢复冲突：`已有同名作品，未覆盖任何文件。`

所有错误都以保留原文件为默认结果。

## 11. 验收标准

必须在实体 iPhone 上逐项执行：

- 首次选择固定总文件夹，第二次运行不再询问；
- 正确识别至少 2 个作品，并忽略无 TXT、无图片和聚合目录；
- 列表名称与 Files 文件夹名称一致；
- 点击作品后剪贴板文案正确，全部图片进入系统分享面板；
- 同日打开分享 2 次后显示“已打开分享 2 次”；
- 取消系统分享面板仍诚实计数；
- 模拟跨日后自动移入 `_相册回收站`；
- 回收站恢复不覆盖同名作品；
- 模拟满 7 天后清理；
- 状态 JSON 损坏时不删除作品并生成备份；
- 权限失效、云文件未下载、移动失败、删除失败均显示可执行提示。

没有完成对应实体 iPhone 操作前，功能必须标记为“已设计未验收”或“已实现未验收”，不得写“测试通过”。

## 12. 已知边界

- 不能确认抖音、小红书等平台是否真正发布；
- 不能自动粘贴目标平台文案或点击发布；
- 不能保证第三方文件提供器中的云文件已下载；
- 不能保证点开头隐藏目录可见；
- 不能在快捷指令未运行时执行次日回收或 7 天清理；
- 不同 iOS 版本的“分享”动作对多图和第三方平台兼容性必须实体测试；
- Personal Automation 不纳入第一版范围。
