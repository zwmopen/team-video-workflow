# 团建视频剪辑工作流

这是本地「团建视频剪辑工作流」项目的私有云端备份仓库。

它保存的是可继续开发的工作流资产，不保存视频素材本体：

- Codex Skill：视频素材分镜、分类、裁去字幕、深度修复等规则。
- 本地工具：素材浏览器、批量处理、音频/文案提取、初剪工作流入口。
- 项目共享记忆：方便其他 AI 工具接手时理解当前约定。
- 处理报告：记录横屏素材清理、VSR/AI 去字测试和后续批量深度修复计划。

## 当前核心规则

1. 原片不直接覆盖，清洗后输出新素材。
2. 分镜素材可以清洗、裁去字幕、删除废料；原片保留为可重切来源。
3. 清洗素材有两种模式：
   - 裁剪模式：裁去字幕、裁切废料、去黑边。
   - 深度修复模式：对无法裁剪但仍有价值的素材，用 VSR/AI 去字作为备用。
4. 横屏裁剪后的分镜普遍可用性差，旧的横屏裁剪分镜已经移入回收站；横屏素材后续优先走深度修复。
5. 以后每个项目都要保留项目共享文档，让其他 AI 工具可以继续接手。
6. 本地工具只做预览、选择、执行确定性处理和结果承载；需要视觉理解、语义匹配、审美判断、修复复核的环节，不强行写成本地按钮，改成 Skill + “复制提示词”。
7. 典型 AI 参与型功能包括：深度修复、智能剪辑/文案配镜、素材分类纠错、成片质检、参考视频学习。
8. 采集、清理、关键词细分和批量改名命令默认只预览；必须显式传入 `--move true` 才执行文件移动。
9. 原视频与同名文案、字幕、封面等 sidecar 文件作为一个事务包移动；任一文件失败时，已移动文件必须自动回滚。
10. 精确重复原视频只允许移动到隔离目录，不得永久删除。
11. 原素材根目录与输出根目录必须相互独立，禁止上下级嵌套，避免扫描时重复吞入生成结果。
12. `rename-clips` 默认 Preview；正式改名必须同时提供 `--move true --confirm-token RENAME`。
13. `apply-visual-corrections` 默认 Preview；正式纠错必须同时提供 `--apply true --confirm-token APPLY`。纠错完成后是否继续统一改名，由 `--rename-after true` 单独控制。
14. 分镜文件移动/改名与 SQLite 场景记录更新按一个逻辑事务执行：任一环节失败时，数据库回滚，已移动文件按反向顺序恢复，新建的空目录清理。
15. CSV 报告和项目导出属于事务后的派生结果；派生输出失败不得伪装成核心文件/数据库事务失败，但必须返回警告。
16. 素材浏览器拒绝非本机 Host、跨站 `Origin`、跨站 `Sec-Fetch-Site` 和非同源 Referer，防止其他网页借浏览器调用本地文件操作接口。
17. 素材浏览器所有 POST 只接受 `application/json`，请求体上限为 1 MB；改名和移到回收站还必须由前端传入服务端确认令牌。
18. 浏览器媒体接口只允许读取素材库和浏览器缓存根目录内的真实文件；符号链接素材不得被改名或删除。
19. 标签与裁剪布局等状态文件通过临时文件加原子替换写入，避免并发或异常退出留下半截 JSON。

## 不进入仓库的内容

- 视频、音频、图片素材
- 缩略图、预览缓存、转录缓存
- VSR 模型、虚拟环境、大型开源仓库
- 任何密钥或本地账号凭据
